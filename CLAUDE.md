# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MakeASound is a C++20 static library that gives platform-agnostic access to audio and MIDI. Two façades make up the device library's public surface, and a second static target builds a plugin core on them:

- `MakeASound::DeviceManager` — audio device enumeration and streaming, backed by [miniaudio](https://github.com/mackron/miniaudio).
- `MakeASound::MidiManager` — MIDI input/output ports, backed by the platform's own MIDI API: Core MIDI on macOS and iOS, WinMM on Windows, the ALSA sequencer on Linux. A platform with none of those fails at configure time rather than building a façade with nothing behind it.
- `MakeASoundPlugin` — the SDK-free plugin core: `Plugin`, parameter groups, versioned state, the module description and `PluginWrapper`, the per-block pipeline every format adapter shares. `plan.md` holds the stages.
- `MakeASoundDSP` — the optional DSP library, built always and linked only by what asks for it: today `DSP::TestSynth`, the instrument `Apps/Synth` and `Plugins/Synth` both play.
- `MakeASoundStandaloneCore` — a `Plugin` run without a host and without a window (`StandaloneHost`: devices, MIDI, the wrapper, `Engine` and the settings file), built wherever the plugin core is, Linux and iOS included.
- `MakeASoundPluginUI`, `MakeASoundPluginWeb` and `MakeASoundStandalone` — each built where the eacp target it needs exists: the generic parameter editor every format shows for a plugin with no editor of its own and the resize grip, an `Editor` over eacp's `WebView` for a plugin whose editor is a React page, and the standalone format's default app, a `StandaloneHost` with its editor and device and MIDI pickers: windows and a menu bar on macOS and Windows, one screen on iOS.
- `MakeASoundVST3` — the VST3 format, a single-component adapter over `PluginWrapper` and the vendored SDK, built wherever `vst3sdk` is on a desktop; pluginval at strictness 10 is its proof.
- `MakeASoundAU` — the AU format, macOS only: one Audio Unit v2 class (`MusicDeviceBase`) over `PluginWrapper` and Apple's AudioUnitSDK (fetched as `ausdk`), built wherever `ausdk` is; `auval -strict` after an install step is its proof.
- `MakeASoundAUv3` — the AUv3 format, an `AUAudioUnit` subclass over `PluginWrapper` in Objective-C++ with no SDK, built on every Apple platform, with its view (an `AUViewController` that is the extension's principal class) where eacp's UI tier is: it ships on iOS, an app extension inside the plugin's standalone app (`FORMATS ... AUv3`), and macOS runs its suites; `Tools/AUv3Probe` in the simulator is its proof.
- `MakeASoundAAX` — the AAX format, macOS only and opt-in: one monolithic AAX Native data model (`AAX_CEffectParameters`) over `PluginWrapper` and Avid's AAX SDK, which CPM fetches (as `aaxsdk`) only under `MAKEASOUND_BUILD_AAX`; Avid's AAX Validator (`aaxval` in DigiShell, the user's own NDA copy) on both examples and a hand check in Pro Tools Developer are its proof. CLAP is a later stage.

Each façade hides its backend behind a pimpl, so no backend types leak into the public headers. The audio side has one backend today; the MIDI side has one per platform behind that same seam.

## Build

Dependencies are fetched automatically by [CPM.cmake](CMake/CPM.cmake) the first time CMake configures — no manual install. The library pulls in miniaudio, [Miro](https://github.com/eyalamirmusic/Miro) (reflection/serialization) and `ea_data_structures`; the demo apps additionally pull in `eacp` (web-UI host), and the plugin core links its `eacp-core` module. The MIDI backends need nothing fetched — they are the platform's own. Their transitive deps (e.g. ResEmbed, NanoTest) come along automatically. Linux additionally needs the ALSA development headers (`libasound2-dev`) installed on the machine — the sequencer backend links against them — and, with the plugin core on, the dev packages eacp's Linux graphics tier configures against (Wayland, xcb, xkbcommon, libdecor, FreeType, HarfBuzz, fontconfig) plus libcurl for eacp-network; `.github/workflows/ci.yml`'s apt step is the list. The tests additionally pull in [ScopedMemoryAllocations](https://github.com/eyalamirmusic/ScopedMemoryAllocations) — **test-only**: `AllocationsChecker` is an INTERFACE target whose sources compile into whatever links it and interpose `malloc`/`new`, so it belongs to `MakeASoundTests` and must never reach `Lib/` or `Apps/`.

```bash
cmake -S . -B build -G Ninja
cmake --build build
./build/Apps/Example/Example     # plain CLI: streams white noise for 2s
./build/Apps/MidiDemo/MidiDemo   # plain CLI: MIDI demo
```

`Apps/Demo` and `Apps/Synth` build macOS `.app` bundles with web (React/Vite) UIs hosted via `eacp`/Miro's webview; their web assets are bundled at build time. `Apps/Synth` links `MakeASoundDSP` and runs its `TestSynth` on `Engine` behind the web page's gain slider and MIDI log.

A plugin is built with `makeasound_add_plugin` from `CMake/MakeASoundPlugin.cmake`, which the top-level `CMakeLists.txt` includes whenever the plugin core is built, so a CPM consumer calls it from its own tree:

```cmake
makeasound_add_plugin(Gain FORMATS Standalone VST3 AU AUv3 AAX OUTPUT_NAME "MakeASound Gain" SOURCES GainPlugin.cpp)
```

It compiles the sources once as the static core `<Name>` (linking `MakeASoundPlugin` PUBLIC) and adds one target per format:

- `<Name>-Standalone`, an executable built from `Plugin/Standalone/StandaloneMain.cpp` (`eacp::Apps::run<StandaloneApp>()`), on Apple a `MACOSX_BUNDLE` with `NSMicrophoneUsageDescription` unless `NO_AUDIO_INPUT` says the plugin declares no input bus (the Synth passes it; the layout is known only at run time, so the flag is the caller's to keep true), on iOS `UIBackgroundModes` `audio` too, at `VERSION` (`EACP_APP_VERSION`, which eacp writes into the plist), and on macOS an ad-hoc `codesign` post-build. On iOS (`_makeasound_ios_bundle`) Ninja adds `CFBundleSupportedPlatforms` (`iPhoneSimulator` when `CMAKE_OSX_SYSROOT` names the simulator, `iPhoneOS` otherwise), `UIDeviceFamily` 1 and 2 and `MinimumOSVersion` to the plist and signs ad hoc for the simulator only, a device build staying unsigned; Xcode writes those keys itself (`TARGETED_DEVICE_FAMILY` `1,2`) and signs automatically with `MAKEASOUND_IOS_TEAM`, otherwise ad hoc (`CODE_SIGN_IDENTITY` `-`, manual) with `CODE_SIGNING_ALLOWED[sdk=iphoneos*]` NO. `STANDALONE_SOURCES <file>...` builds it from the plugin's own app instead, its `main` and app class composing `StandaloneHost` and whichever of `SettingsPanel`, `GenericEditor` and `editorWindowOptions` it wants through `<MakeASound/Plugin/Standalone/MakeASoundStandalone.h>`, and `STANDALONE_LIBRARIES <target>...` is whatever else it links. It still links `MakeASoundStandalone` (then the libraries, then the core), so the pieces are there to take while the unreferenced `StandaloneApp` objects stay out of the link, and it keeps the default app's bundle, plist, microphone string and signing; either argument without the `Standalone` format, or the libraries without the sources, is a configure error.
- `<Name>-VST3`, a `MODULE` built from the entry files recorded on `MakeASoundVST3` (`MAKEASOUND_VST3_ENTRY`, our `GetPluginFactory`) and `vst3sdk` (`MAKEASOUND_VST3_SDK_MAIN`, the SDK's `bundleEntry`/`InitDll`/`ModuleEntry`), linking `MakeASoundVST3` before the core. Every bundle lands in `<build>/VST3/<OUTPUT_NAME>.vst3`, the output directories wrapped in `$<1:...>` so a multi-config generator adds no per-config folder, and the import library and `.pdb` kept out of it in the target's own binary dir; the bundle path is the target property `MAKEASOUND_VST3_BUNDLE`. On macOS it is `BUNDLE` + `BUNDLE_EXTENSION vst3` with `Plugin/VST3/VST3Info.plist.in` (`BNDL`, identifier `<BUNDLE_ID>.vst3`, one per format because the macOS Installer resolves components by bundle id), the SDK's `macexport.exp` as `-exported_symbols_list` (so `nm -gU` shows exactly `_GetPluginFactory`, `_bundleEntry`, `_bundleExit`), and a post-build that copies `Plugin/VST3/PkgInfo` (the 8 bytes `BNDL????`) into `Contents/` and then ad-hoc signs the bundle. On Windows it is `<Out>.vst3/Contents/<arch>-win/<Out>.vst3`, the arch from `CMAKE_CXX_COMPILER_ARCHITECTURE_ID` (`x86_64`, `arm64`, `x86`); on Linux `<Out>.vst3/Contents/<CMAKE_SYSTEM_PROCESSOR>-linux/<Out>.so`, linked with `Plugin/VST3/VST3Exports.map` as `--version-script` (`GetPluginFactory`, `ModuleEntry`, `ModuleExit`, `local: *`).
- `<Name>-AU` (macOS only), a `MODULE` built from the two files recorded on `MakeASoundAU`, `MAKEASOUND_AU_ENTRY` (`EntryPoint.cpp`, the factory) and `MAKEASOUND_AU_VIEW_SOURCE` (`CocoaUI.mm`, or `NoCocoaUI.cpp` where there is no UI tier), linking `MakeASoundAU`, then the core, then `MAKEASOUND_AU_VIEW_LIBRARIES`, with `-fobjc-arc` on the Objective-C++, `OBJCXX_STANDARD 23` and Release LTO. `MAKEASOUND_AU_VIEW_CLASS` is defined per module as `MakeASoundAUView_<id>`, `<id>` being `string(MAKE_C_IDENTIFIER "<BUNDLE_ID>_<VERSION>")`, because the Objective-C runtime is one per process and two components defining one class would share whichever loaded first. The bundle, `<build>/AU/<OUTPUT_NAME>.component` (the property `MAKEASOUND_AU_BUNDLE`), is laid out by hand rather than as a `BUNDLE` target, the module landing in `Contents/MacOS` (the output directory wrapped in `$<1:...>`), because CMake rewrites a bundle target's `Info.plist` on every configure and would undo the generated one until the next relink; `MAKEASOUND_AU_EXPORTS` (`AUExports.txt`) as `-exported_symbols_list` with `LINK_DEPENDS`, so `nm -gU` shows exactly `_MakeASoundAUFactory` and `_MakeASoundAUWritePlist`. The module depends on `MakeASoundAUPlistGen`, the one plist tool every AU module shares (targets are global, so a CPM consumer's directory names it too); the module's post-build runs `$<TARGET_FILE:MakeASoundAUPlistGen>` on `$<TARGET_FILE:<Name>-AU>` to write `Contents/Info.plist` from the module's own `describeModule()` (module binary, bundle name, identifier `<BUNDLE_ID>.component`, executable, output path), copies `MAKEASOUND_AU_PKGINFO` (the VST3 directory's `PkgInfo`, the same 8 bytes) into `Contents/`, and ad-hoc signs the bundle over both. Its `CFBundleVersion` and `CFBundleShortVersionString` are `ModuleDescription::version`, not `VERSION`, because macOS caches a bundle's `AudioComponents` keyed by `CFBundleVersion`.
- `<Name>-AUv3` (iOS only, a status line elsewhere; `AUv3` without `Standalone` in the same call is a configure error, a custom app counting), the app extension `<OUTPUT_NAME>.app/PlugIns/<OUTPUT_NAME>.appex`, identifier `<BUNDLE_ID>.auv3`: an executable (no framework, so the core is linked into the app and the extension each) built from `MAKEASOUND_AUV3_MAIN` (`ExtensionMain.cpp`, a `main` over `NSExtensionMain`, declared `extern "C"` there since no header does) and `MAKEASOUND_AUV3_SOURCES` with `MAKEASOUND_AUV3_CLASS_SUFFIX` defined as the AU view's `<id>`, compiled and linked with `-fapplication-extension` and `-fobjc-arc` on the Objective-C++, linking `MakeASoundAUv3`, the core and `MAKEASOUND_AUV3_VIEW_LIBRARIES`, Release LTO; the app depends on it. Its plist, `<binary dir>/<Name>-AUv3-Info.plist` from the custom target `<Name>-AUv3-Plist`, is `writeAppExtensionPlist` run by `<Name>-Describe` (bundle name, identifier, executable, principal class `<MAKEASOUND_AUV3_PRINCIPAL_CLASS>_<suffix>`, `MAKEASOUND_AUV3_HAS_VIEW` as 0 or 1, output), then `plutil` sets `CFBundleVersion` and `CFBundleShortVersionString` to `VERSION`, since an extension's version must be its app's. **The plist tool for a cross build**: an iOS binary can be neither loaded nor run on the build machine, and the component type needs the plugin constructed, so the first `AUv3` call schedules (`cmake_language(DEFER)` to the end of the top-level configure) `MakeASoundDescribeBuild`, an `ExternalProject` that configures the same top-level project again for macOS into `<build>/MakeASoundDescribe` (Ninja, else Makefiles; Debug; `CMAKE_OSX_SYSROOT=macosx`; `MAKEASOUND_DESCRIBE_BUILD` ON, apps and tests off; `MAKEASOUND_BUILD_EXAMPLES`, `_UNITY_BUILD`, `_CI_BUILD`, the C, C++ and Objective-C++ compiler launchers and `CPM_SOURCE_CACHE` forwarded, every package in `CPM_PACKAGES` pointed at the source this tree already has through `CPM_<name>_SOURCE`, so nothing is fetched again; then `MAKEASOUND_DESCRIBE_CMAKE_ARGS`) and builds every `<Name>-Describe` (`BUILD_ALWAYS`, the tools as byproducts), its steps under `cmake -E env --unset=SDKROOT --unset=IPHONEOS_DEPLOYMENT_TARGET --unset=MACOSX_DEPLOYMENT_TARGET`, since an Xcode build exports them to every script. In that build `makeasound_add_plugin` makes the core and, for an `AUv3` call, `<Name>-Describe` (`MakeASoundAUDescribe`'s `MAKEASOUND_AU_DESCRIBE_MAIN`, `DescribeMain.cpp`, plus the core) in `<sub-build>/Describe`, and returns; the top level skips `ThirdParty/`, `Apps/`, `Tools/` and `Tests/`, and `Plugin/` adds only `AU/`, so a web editor builds its fallback and runs no npm. A plugin's sources must therefore build for macOS, and a consumer's tree is configured twice. Under Ninja the extension is laid out by hand (`MACOSX_BUNDLE FALSE`, the output directory `$<1:...>` inside the app's bundle, the property `MAKEASOUND_AUV3_BUNDLE`, the plist a `LINK_DEPENDS`); its post-build copies the plist in and, for the simulator, signs it ad hoc and re-signs an already-linked app (`CMake/SignBuiltBundle.cmake`), whose own post-build signs it over the extension otherwise. Under Xcode it is a `MACOSX_BUNDLE` with `BUNDLE_EXTENSION appex`, `XCODE_PRODUCT_TYPE com.apple.product-type.app-extension`, `INFOPLIST_FILE` the generated plist (Xcode adds the platform keys; the plist must not carry them), `APPLICATION_EXTENSION_API_ONLY`, `CLANG_ENABLE_OBJC_ARC` (Xcode drops the per-language `-fobjc-arc`) and the app's signing, and the app embeds it with `XCODE_EMBED_APP_EXTENSIONS`, which copies but does not build it.
- `<Name>-AAX` (macOS, with `MAKEASOUND_BUILD_AAX` only), a `MODULE` built from `MAKEASOUND_AAX_ENTRY` (`EntryPoint.cpp`: `GetEffectDescriptions`, and the SDK's `AAX_Init.cpp` included with its `AAXShutdown` renamed) and the SDK's `Interfaces/AAX_Exports.cpp` (`aaxsdk`'s property `MAKEASOUND_AAX_SDK_EXPORTS`), linking `MakeASoundAAX` before the core, with `MAKEASOUND_AAX_BUNDLE_ID="<BUNDLE_ID>"` and `MAKEASOUND_AAX_PACKAGE_NAME="<OUTPUT_NAME>"` defined and Release LTO. The bundle, `<build>/AAX/<OUTPUT_NAME>.aaxplugin` (the property `MAKEASOUND_AAX_BUNDLE`), is laid out by hand as the `.component` is, the module landing in `Contents/MacOS` (the output directory wrapped in `$<1:...>`); `MAKEASOUND_AAX_EXPORTS` (`AAXExports.txt`) is the `-exported_symbols_list` with `LINK_DEPENDS`, so `nm -gU` shows exactly the seven ACF entry points `_ACFRegisterPlugin`, `_ACFRegisterComponent`, `_ACFGetClassFactory`, `_ACFCanUnloadNow`, `_ACFStartup`, `_ACFShutdown` and `_ACFGetSDKVersion`. An AAX host reads a plugin's identity from `GetEffectDescriptions`, not the plist, so `MAKEASOUND_AAX_PLIST` (`AAXInfo.plist.in`: `CFBundlePackageType` `TDMw`, signature `PTul`, identifier `<BUNDLE_ID>.aaxplugin`, name and executable `OUTPUT_NAME`, both versions `VERSION`, copyright `COMPANY`) is configured at configure time rather than written after the link; the post-build copies it and `MAKEASOUND_AAX_PKGINFO` (AAX's own `PkgInfo`, the 8 bytes `TDMwPTul`) into `Contents/` and ad-hoc signs the bundle over both. Pro Tools Developer loads that; retail Pro Tools loads only a bundle PACE's `wraptool` signed. With `AAX_WCGUID <guid>` on `makeasound_add_plugin` (the PACE wrap configuration; a public id, useless without the account), `MAKEASOUND_PACE_SIGN_ID` (a Developer ID Application identity) set and wraptool at `MAKEASOUND_PACE_WRAPTOOL` (default `/Applications/PACEAntiPiracy/Eden/Fusion/Current/bin/wraptool`), a next post-build runs `CMake/SignAAXBundle.cmake`: `wraptool sign --verbose --autoinstall on [--account MAKEASOUND_PACE_ACCOUNT] --wcguid --signid --in --out` on the bundle in place, a failure a warning. No password is ever passed: wraptool takes it from the keychain, saved there by one `wraptool sync --account <a> --password <p>` outside the build, whose account becomes its default when `MAKEASOUND_PACE_ACCOUNT` is empty. The Synth example names its GUID; signing from a non-interactive shell has not yet been seen to work (wraptool reported no password there after a terminal sync).

`OUTPUT_NAME` is the bundle and window name, `BUNDLE_ID` defaults to `com.makeasound.<name>` lowercased, `COMPANY` (default `MakeASound`) is the company eacp embeds in the app's `AppInfo` and the VST3 and AAX plists' copyright, and `VERSION` (default `1.0.0`) is the app's, the AUv3 extension's, the VST3 bundle's and the AAX bundle's version string and part of the AU view's and the AUv3 classes' names; a VST3 host reads the plugin's version from the factory instead, which reports `PluginDescription::version`, and the AU plist and the AAX package version (`SetPackageVersion`) take `ModuleDescription::version`. The settings file is filed under `describeModule()`'s `vendor` and the plugin's `name()`, so the two can differ. A format whose target was not built (`MakeASoundStandalone`, `MakeASoundVST3`, `MakeASoundAU`, `MakeASoundAUv3`, `MakeASoundAAX`) is skipped with a status line, as is `AUv3` off iOS; an unknown format is a configure error. The function tests those targets and reads every file path from their properties, because targets are global where a consumer's directory cannot see MakeASound's variables. With `MAKEASOUND_INSTALL_PLUGINS` on (the default), a last post-build runs `CMake/InstallPluginBundle.cmake`, a best-effort copy (a failure is a warning) into `~/Library/Audio/Plug-Ins/VST3`, `%LOCALAPPDATA%/Programs/Common/VST3` or `~/.vst3`, a component into `~/Library/Audio/Plug-Ins/Components`, and an `.aaxplugin` into `/Library/Application Support/Avid/Audio/Plug-Ins`, a system folder a user usually cannot write, so that copy normally warns. The script runs each step through `cmake -E` under `execute_process` with its errors quieted, because `file()` stops a script on a folder it cannot write, and the warning says a system folder needs write access.

A plugin whose editor is a web page adds `makeasound_add_web_editor` from `CMake/MakeASoundWebEditor.cmake`, which `Plugin/CMakeLists.txt` includes after `MakeASoundPlugin.cmake`, called after `makeasound_add_plugin`:

```cmake
makeasound_add_web_editor(SynthPlugin WEB_DIR ${CMAKE_CURRENT_SOURCE_DIR}/web SOURCES SynthEditor-Web.cpp FALLBACK_SOURCES SynthEditor-None.cpp)
```

Its other arguments are `[API <type>... API_HEADER <header>...]`, Miro APIs beside `MakeASound::Web::ParameterApi`, and `[CATEGORY]` (default `<Name>Editor`). Where `MakeASoundPluginWeb` is a target it runs `miro_export` as `<Name>EditorSchema` (the API header from that target's property `MAKEASOUND_WEB_API_HEADER`) and eacp's backend, mock and React-hook generators into `<WEB_DIR>/src/generated`, links the codegen tool `<Name>EditorSchema_Codegen` against `MakeASoundPluginWeb` when it exists (not when cross-compiling, iOS included, where the committed `src/generated` stands in), and calls `eacp_webview_add_vite(<Name> NAMESPACE <Name>Editor CATEGORY <category>)`: `npm install` at configure when `<WEB_DIR>/node_modules` is missing, `vite build` in the build into the binary dir, and the result embedded through ResEmbed as an INTERFACE source of the static core, so every format target linking the core carries the page in its own image. It then links `MakeASoundPluginWeb` PUBLIC, adds `SOURCES` to the core and defines `MAKEASOUND_WEB_DEV_SERVER` for `WebEditorOptions::devServer` (`"http://localhost:5173"` under `EACP_WEBVIEW_DEV`, which skips the vite build and the embed, `""` otherwise). Where `MakeASoundPluginWeb` is not a target (Linux) it adds `FALLBACK_SOURCES` and runs no npm. Node and npm are therefore needed to configure a tree with the examples on macOS, Windows and iOS; `MAKEASOUND_BUILD_EXAMPLES=OFF` keeps a plugin-core build free of them. `<WEB_DIR>/.gitignore` keeps `node_modules`, `.vite` and `dist` out; `src/generated` and `package-lock.json` are committed. `makeasound_add_plugin` knows nothing of it: the page rides in the core.

```bash
open "./build/Plugins/Gain/MakeASound Gain.app"     # the effect example
open "./build/Plugins/GainApp/MakeASound Gain App.app"   # the effect in an app of its own
open "./build/Plugins/Synth/MakeASound Synth.app"   # the instrument example
./build/Tools/PluginValidator/PluginValidator build/VST3   # every .vst3 there, strictness 10
./build/Tools/PluginValidator/PluginValidator build/AU     # every .component there, auval -strict
./build/Tools/PluginValidator/PluginValidator --aax-tools <validator> build/AAX   # every .aaxplugin there, aaxval
```

`AUv3Probe` (`Tools/AUv3Probe/`, iOS only) is a host's first minute with an installed AUv3, as a command-line tool for `xcrun simctl spawn <udid> AUv3Probe <app or appex>...`: for each `AudioComponents` entry of each extension (an app standing for every `PlugIns/*.appex`) it waits up to 30 s for `AudioComponentFindNext` to find it with `kAudioComponentFlag_IsV3AudioUnit`, instantiates it (out of process: `AUAudioUnit_XH`), renders 16 blocks of 512 (an effect fed a 440 Hz sine at half scale through the pull block, an instrument a middle C through `scheduleMIDIEventBlock`) wanting a peak above 0.01, and asks for the view controller, printing `PASS`/`FAIL` per component and exiting with the number that failed. In a windowless process the remote controller reports the screen's size, not the editor's.

`PluginValidator` (`Tools/PluginValidator/`, added with `Plugins/` when `MakeASoundPluginval` is a target) is pluginval, auval and aaxval as an executable, so CLion, CI and a test all run it the same way: `[--strictness N] [--skip-gui-tests] [--timeout-ms N] [--version vX.Y.Z] [--stress N] [--aax-tools <dir>] [--logs <dir>] <bundle or folder>...`, each `.vst3`, `.component` or `.aaxplugin` named and every one of those in each folder named (a directory ending in one of those extensions is a bundle, not a folder); nothing to validate prints the usage and exits 1. A `.component` goes through auval (see `Plugin/Validation/`): it is copied into `~/Library/Audio/Plug-Ins/Components`, replacing the one there, and each of its `AudioComponents` runs through `auval -strict -v`, `--stress N` adding `-stress N`; pluginval is fetched only when a `.vst3` is among the bundles, so `PluginValidator build/AU` touches no network. It depends on no plugin target and has no compiled-in folder, so it validates a bundle from any tree, and running it from CLion does not build the plugins first. The first run downloads Tracktion's pluginval v1.0.4 into eacp's resource folder (`OnlineResource::defaultDirectory()`, under the app's Application Support); later runs find it there and touch no network, and a new `--version` downloads again. It runs each bundle with `--strictness-level 10 --timeout-ms 120000 --verbose`, prints `PASS <name> (N s)` or `FAIL <name> (exit N, N s)` with the last 25 non-blank lines and the path of the full log (`<logs>/<bundle>.log`, the system temp folder's `PluginValidator/` unless `--logs` says where), and exits with the number that failed. Tracktion publishes no Windows ARM64 build, so there it stops with an error. Its editor tests open each editor briefly; nothing plays. Off macOS a `.component` fails with "AU validation is macOS only". An `.aaxplugin` goes through Avid's AAX Validator, which Avid ships under NDA and which is therefore never fetched: `--aax-tools <dir>`, or the environment variable `MAKEASOUND_AAX_TOOLS`, names the unpacked validator folder (the one holding `CommandLineTools/dsh`), and with neither the bundle fails with "AAX validation needs --aax-tools"; pluginval is not fetched for it either. The bundle is not installed: aaxval takes its absolute path. DigiShell is driven over stdin, twice: `load_dish aaxval`, `listtests {detail: min, stringformat: yaml}` and `exit`, then `load_dish aaxval`, one `runtest {test: <id>, path: "<bundle>", stringformat: yaml, runmode: serial}` per listed test and `exit`, rather than one `runtests`. A test passes on `E_COMPLETED_PASS` and is not applicable on `E_CANCELED`, and the log gets one `PASS`, `N/A`, `FAIL` or `SKIP` line per test. Two tests are skipped by id, each logged with its reason: `test.cycle_counts` (HDX only: its script loads the DAE dish and acquires a deck, which without HDX ends `E_LOST` about as often as `E_CANCELED`) and `test.page_table.load` (fails outright for a plugin that ships no page table). A dsh that prints nothing for 10 minutes is killed with whatever it forked, a quarantined `dsh` gets the `xattr -dr com.apple.quarantine` hint, and dsh listens on a fixed port, so two must never run at once. Nothing runs aaxval but this tool: no CI step and no env-gated test. Against the 2024.6.0 validator both examples pass every other test with no warning. Off macOS an `.aaxplugin` fails with "AAX validation is macOS only".

To point CPM at a local checkout of a dependency instead of fetching, pass e.g. `-DCPM_Miniaudio_SOURCE=/path/to/miniaudio` at configure time.

CMake options: `MAKEASOUND_UNITY_BUILD` (jumbo build of our own targets, the example plugin cores included, OFF), `MAKEASOUND_CI_BUILD` (OFF; the flag set CI configures with: it forces `MAKEASOUND_UNITY_BUILD`, eacp's `EACP_CI_BUILD`, which is eacp's and Miro's unity builds with eacp's precompiled header left off, and `ESIMD_UNITY_BUILD`, as cache entries so the dependencies see them when CPM configures them; ## Architecture

Public surface: `Lib/MakeASound/MakeASound.h` is the device library's umbrella public header, and `Lib/MakeASound/Plugin/MakeASoundPlugin.h` the plugin core's, which includes the first. Downstream code does `#include <MakeASound/MakeASound.h>`, a plugin `#include <MakeASound/Plugin/MakeASoundPlugin.h>`. The include root is `Lib/` (so the umbrella resolves as `<MakeASound/MakeASound.h>`); cross-module headers inside the library include each other by relative path.

Code under `Lib/MakeASound/` is grouped into domain folders, each compiled as separate TUs:

- **`Audio/`** — `Buffer` and `Channel`. `Buffer` is the one planar (channel-major) block type, **owning or referring**: constructed with a channel and sample count it owns zeroed storage; constructed over a `float* const*` table it refers to someone else's. Every access goes through that table plus a start offset, so `getSubBuffer(start, length)`, `getChannelSubset(first, count)` and `getSingleChannel(c)` are further `Buffer`s over the same table with no storage and no channel cap, and offsets compose. It is **move-only**: a copy is a compile error, `Buffer::copyOf` is the deep copy, `getSubBuffer(0)` the alias. `setSize` zeroes and never releases capacity; `referTo` drops owned storage. Constness lives in the reference — a `const Buffer` hands out `ConstChannel`s and cannot be sliced. `Channel` (`EA::Span<float>`) and `ConstChannel` are the single-channel currency used everywhere in place of a bare span. Sizes and indices are `int` throughout. Everything that does not allocate is `noexcept`; the allocating members are the owning constructor, `setSize` and `copyOf`, and `Tests/AllocationTests.cpp` pins that the rest stays off the heap.
  - `BusLayout.h`, `Playhead.h`, `ProcessContext.{h,cpp}` and `Processor.h` are the format-neutral processing vocabulary. `BusLayout` (`Bus {name, numChannels, isMain}`, `MidiBus {name}`, four vectors, `stereoInOut()` / `stereoOut()` / `instrument()`, `acceptsExactly`) is Miro-reflected; bus 0 on each side is the main one. `ProcessSpec {sampleRate, maxBlockSize, layout}` keeps rates `int` like `DeviceManager`; adapters round at their boundary. `ProcessContext` holds `Vector<Buffer>` inputs/outputs that **refer** to memory the host owns, `Vector<MIDI::Buffer>` in/out, a `Playhead` and an empty `ParameterChanges` placeholder; `clearMidi()` clears every MIDI buffer, `clearMidiOut()` the output half; `prepare(layout)` sizes the vectors and reserves every MIDI buffer, and the `main*()` accessors hand back bus 0 or a stand-in for an undeclared bus (an empty `Buffer`, a reserved `MIDI::Buffer` that reads empty) so code written against `mainOutput()` never indexes out of range. `Processor` is `getBusLayout()`, `prepare(const ProcessSpec&)`, `process(ProcessContext&) noexcept` and `reset() noexcept`; `reset` is a real virtual because Plug had to fake one in its AU adapter.

- **`Devices/`** — plain-data types and the audio façade.
  - `DeviceInfo.{h,cpp}` holds backend-independent structs/enums (`DeviceInfo`, `StreamConfig`, `StreamParameters`, `StreamOptions`, `Flags`, `AudioCallbackInfo`, `Error`, `AudioCallbackStatus`, `Callback`). No backend types leak in. `AudioCallbackInfo` is a copyable POD holding the backend's channel tables (`inputChannels`/`outputChannels`) and counts; `getOutput()` / `getInput()` build referring `Buffer`s over them per call, so `auto out = info.getOutput()` is free. It carries a `dirty` flag, raised when the stream shape (channels, sample rate, block size) changes since the previous callback — the signal for consumers to (re)allocate working buffers. Data structs opt into Miro JSON reflection in-place via `MIRO_REFLECT(...)`.
  - `DeviceManager.{h,cpp}` is the audio façade. It holds an `OwningPointer<MiniAudio::DeviceManager>` pimpl; the header forward-declares the backend type and the destructor is defined out-of-line in `.cpp` so the deleter sees the complete type. The `.cpp` is the only place that constructs the backend (`EA::makeOwned<MiniAudio::DeviceManager>()`).
  - `DeviceQueries.{h,cpp,mm}` plus `DeviceQueriesIOS.mm` is what the platform can say about a device without opening it: supported block sizes, its current sample rate, the route's own latency, the name the platform gives its own default device, and (iOS only) the route's native format. One TU per platform — Core Audio's HAL on macOS, `AVAudioSession` on iOS, conservative fallbacks elsewhere. The backend consults these where the platform's answer beats miniaudio's: `resolveDefaults` prefers the platform's default-device name because miniaudio marks several capture devices default on Core Audio, and `getStreamLatency` adds `getRouteLatency` to the periods it can see.
  - `AudioSession.{h,cpp}` plus one platform TU (`AudioSession-iOS.mm`, `AudioSession-Default.cpp`) is the platform audio session — `SessionCategory`, `SessionOptions`, `SessionConfig`, `SessionState`. Only iOS has one; elsewhere `hasAudioSession()` is false and the calls are no-ops. The backend applies it on **every** open (recovery's included) and it **follows the StreamConfig** where the app has not overridden it: category from whether there is an input side, preferred rate and block size from the config. miniaudio is initialised with `ma_ios_session_category_none` + `noAudioSessionActivate` so it never touches the session itself — preserve that when editing `initContext`. Interruptions and route changes need nothing of their own: on `InterruptionBegan` miniaudio stops the device, whose `Stopped` sends recovery to re-open (the session re-applied) every 250 ms until the session can activate again; a route change is `Rerouted` with the stream kept, and a media-services reset, which miniaudio does not observe, starves the callback until the watchdog recovers it. `InterruptionEnded`'s should-resume option is not consulted.
  - `Engine.{h,cpp}` runs a `Processor` on a `DeviceManager` stream with a `MidiManager`'s open inputs on its main MIDI bus: `prepare(processor, rate, block)` binds and prepares, `start(config, processor)` prepares then opens the stream (dropping the config's capture side when the layout has no input bus, so an instrument costs no microphone permission), and `process(AudioCallbackInfo&)` is the callback, public so a host with its own stream or a test can drive it. It owns the `ProcessContext`, the `MidiBlockSync` and two one-channel stand-ins: `silence` for an input bus channel the device cannot feed and a `bin` for an output bus channel it cannot play; a bus channel past a device that has *some* inputs reads device channel 0, so a mono mic spreads across a stereo bus. The main buses `referTo` the callback's tables through per-block pointer tables, nothing is copied, and device channels past the bus are cleared. A `dirty` block resets the processor and the MIDI window; one whose rate or block size differs from the spec re-prepares first, on the audio thread, the one documented allocation there. MIDI out buses are cleared and ignored here; the standalone format sends its plugin's MIDI out through `Standalone::MidiSender` instead (the header's comment still says it "arrives with the standalone format").

- **`MIDI/`** — MIDI types, the backend seam and the MIDI façade: `MIDI.{h,cpp}` (typed events + raw-byte conversion), `MidiInfo.{h,cpp}` (port info, event/message wrappers, `MidiNotification`), `MidiBlockSync.{h,cpp}` (aligns incoming MIDI to audio block boundaries), and `MidiManager.{h,cpp}` (façade with an `OwningPointer<MidiBackend>` pimpl, same out-of-line-destructor pattern). Nothing here names a backend.
  - `MidiBackend.h` is the abstract interface a platform implements, and the free `makeMidiBackend()` is what the façade constructs — defined in one TU per platform (`CoreMIDI/CoreMIDI-Factory.cpp` on Apple, `WinMIDI/WinMIDI-Factory.cpp` on Windows, `ALSA/ALSA-Factory.cpp` on Linux), selected in `Lib/CMakeLists.txt` the way `DeviceQueries` is. `MidiBackend` also carries the notification plumbing so every backend shares it: `notifyHost()` feeds both a `notificationCallback` delivered on the platform's MIDI thread and a mutex-guarded queue the host drains with `MidiManager::drainNotifications()` — the audio side's two-path design, same names.
  - `MidiPortRegistry.{h,cpp}` is `idForDevice`'s rule for MIDI: a port id is a slot keyed by the platform's stable identity (`kMIDIPropertyUniqueID` under Core MIDI, the device name plus its index under WinMM, the `client:port` pair under ALSA), not a position in the enumeration, so a hotplug does not renumber the other ports and a cached id keeps naming what it named. Backends scan through `beginScan()`/`idFor()` and resolve an id back to the current port number at open time. Virtual ports keep negative ids, which no registry hands out.
  - `MidiManager::now()` is the clock every backend stamps `MidiInputEvent::arrival` on, so `MidiBlockSync` compares like with like.
  - `MidiParser.{h,cpp}` is the platform-agnostic byte-stream parser (running status, interleaved realtime, bounded SysEx assembly into a buffer the owner hands in) that every native backend feeds raw packets into — pure and allocation-free, so it is covered by the allocation tests. `setIgnoredTypes(clock, activeSense)` reaches it through the façade, ports already open included.

- **`Plugin/`** — the `MakeASoundPlugin` target, with its own `CMakeLists.txt` (which finds eacp, adds `UI/`, `Web/`, `Standalone/`, `VST3/`, `AU/`, `AUv3/`, `AAX/` and `Validation/` and includes `MakeASoundPlugin.cmake` and `MakeASoundWebEditor.cmake`): SDK-free, namespace `MakeASound`, nothing from a format SDK, and no eacp header included by any header: `Core/Editor.h` forward-declares `eacp::Graphics::View` and nothing more, so the target links no GUI tier. The only file in the directory itself is the umbrella `MakeASoundPlugin.h`; the code is in `Parameters/` (`Parameter`, `FloatParam`, `ChoiceParam`, `BoolParam`, `CommonParams`, `ParameterGroup`, `ParameterList`, `ParameterIdentity`), `State/` (`StateContext`, `State`), `Core/` (`Description`, `Identity`, `Editor`, `HostEditListener`, `Plugin`, `StatePlugin`), `Host/` (`PluginWrapper`), `Realtime/` and `Compat/` (`JuceTree`, `JuceState`, `ApvtsXml`: what a JUCE build of the plugin saved, read back; `JuceIdentity`: what a JUCE build names things by). A plugin TU includes `<MakeASound/Plugin/MakeASoundPlugin.h>` and defines `describeModule()`.
  - **Parameters.** `Parameter` is the abstract base: range and default, `numSteps`, plain and normalized get/set, text in and out, a state text form, `versionHint()` and `curve()` (`Curve {Linear, SquareRoot, Squared, Cubed, CubeRoot, Other}`, the shape of `toNormalized` as an AU host can be told of it; the base's linear mapping answers `Linear`, and an override of `toNormalized`/`toPlain` with another shape overrides it too). The concrete ones are `FloatParam`, `IntParam`, `ChoiceParam`, `BoolParam` and, in `CommonParams.h`, `DecibelParam`, `HzParam`, `TimeParam`, `PercentParam`; each takes a trailing `ParameterOptions` (`id`, `shortName`, `label`, `automatable`, `bypass`, `sessionOnly`, `hostId`, `hostKey`, `aaxId`, `versionHint`) written with designated initialisers. `isDiscrete()` and `isBoolean()` are JUCE's (a choice and a bool discrete, a bool boolean, an int or a stepped float neither, false in the base), read only by the JUCE-mode AU range. Values are relaxed atomics read directly on the audio thread; a non-finite write is dropped. An id defaults to the name; `id` pins it so a rename keeps saved state and automation. **Pin before regrouping:** the state key and the host id both come from the id *path*, so moving a parameter into, out of or between named groups changes both, and breaks every session and automation lane, unless `id` and `hostId` are pinned first (`ParameterOptions`' comment and the README say so too); FNV-1a over the path stays the default (JUCE hashes the leaf id with ×31, which has structured collisions such as "Aa"/"BB"). `versionHint` (`int`, 0 unset) is JUCE's `ParameterID::versionHint`, the release that added the parameter: it orders the AU v2 parameter list (below). `FloatRange.h` is `FloatRange {min, max, interval, skew, symmetricSkew}`, header-only, with `withCentre(min, max, centre[, interval])` (JUCE's `setSkewForCentre`), `toNormalized`, `toPlain`, `snap`, `isLinear` and `numSteps` (`int((max - min) / interval)` when `interval > 0` and the curve is linear, 0 otherwise, so a skewed grid is continuous to a host and its values still snap, as every JUCE float is): JUCE's `NormalisableRange<float>` statement for statement in float, so normalize, denormalize and snap give JUCE's bits (a sweep of ~2M inputs over 13 ranges, skew, symmetric skew, intervals and `withCentre` included, matched JUCE 8.0.12 bit for bit at -O0 and -O2 on arm64 macOS; another libm may differ in a transcendental's last bit). `FloatParam(name, min, max, default, options)` is `FloatParam(name, FloatRange {min, max}, default, options)`; it stores the snapped value, normalizes as `RangedAudioParameter` does (`toNormalized(snap(v))`, `snap(toPlain(clamp(n)))`), reports `range()`, and its `curve()` names a skew of exactly 1, 0.5, 2, 3 or 1/3 (not symmetric) and answers `Other` for the rest. `DecibelParam`, `HzParam` and `TimeParam` take a `FloatRange` overload too; `HzParam(name, min, max, ...)` is `withCentre` at √(min·max) (`HzParam::rangeFor`), linear when `min <= 0`. `IntParam(name, min, max, default, options)` (`IntParam.h`, header-only) has `numSteps` `max - min`, integer text and state, and `get()` as an `int`; it and `ChoiceParam` map through `Parameter::indexToNormalized`/`indexToPlain`, JUCE's `AudioParameterInt`/`AudioParameterChoice` range (linear, rounded half to even through an integer as `juce::roundToInt`, so -0.4 gives +0); a plain `setValue` and `valueToText` round the same way, a choice's included (it used `lround`, so 0.5 gave 1 where the normalized path gave 0). A plugin declares its parameters in a `ParameterGroup` subclass (`ParameterGroup.{h,cpp}`) that registers members with the protected variadic `add(...)` in its constructor: parameters, groups, pointers to either (`OwningPointer`) and ranges of any of those (`std::array`, `EA::Array`, `std::vector`, `EA::Vector`), in declaration order, which is the automation order. A group takes `(name, GroupOptions {id, automatable})`; the root normally has no name, and a nameless group adds no segment to either path. It holds pointers to its members, so it neither copies nor moves, and `add` is constructor-time only. A duplicate id within one group (a nameless child shares its parent's key space) asserts. `forEach` walks the leaves depth-first with id path `"Osc 1/Attack"`, display path `"Osc 1 Attack"` and the AND of the leaf's and every enclosing group's `automatable`; `ParameterList` is built from a group through it, each `Entry` carrying `groups`, the named groups around it outermost first (`EnclosingGroup {id, name, identifier, ownId}`, the id an id path, `ownId` the group's own, `identifier` the AUv3 group identifier: the path, or `ownId` under a JUCE scheme), which the AUv3 tree is built from; `bypassIndex()` is its first host-exposed entry whose parameter `isBypass()` (-1 with none; a second asserts and is ignored), and that entry's `Entry::bypass` is true, so a non-automatable bypass parameter is no bypass to a host; `addHostBypass(param)` appends one more such entry (exposed, no group, the parameter's own id and name, re-indexing the host ids), a no-op when the list has a bypass already, and is how `PluginWrapper` adds its own. The host id is FNV-1a of the id path masked to 31 bits (`hostIdFor`), because VST3 reserves ids from 2^31 up, unless `ParameterOptions::hostId` names one, which must be below 2^31 too (asserted). Host ids are sorted for `indexOfHostId` and a collision asserts in debug. **Every id a host stores is on the `Entry`**, computed for the list's `ParameterIdentity` (`identity()`; the constructor takes one, default MakeASound's, and `setIdentity` recomputes, re-indexes and checks): `hostId` (the VST3 `ParamID` and AU `AudioUnitParameterID`), `hostKey` (the parameter's `hostKey()`, its leaf id unless `ParameterOptions::hostKey` names one: JUCE's `paramID`), `address` (the AUv3 `AUParameterAddress`, found with `indexOfAddress` through a sorted table), `identifier` (the AUv3 identifier), `aaxId` (the `AAX_CParamID`, found with `indexOfAAXId`), `addedBypass` and `listedInAU`. Under MakeASound's scheme they are exactly what the adapters computed before (address the host id, identifier the id path, AAX id the host id in eight lowercase hex digits). Under `IdScheme::JUCE`: `hostId` is `Compat::juceStringHash(hostKey)` masked to 31 bits unless `juceStudioOneMask` is off (then an explicit `hostId` may be 2^31 or more too), the added bypass `juceVst3BypassId` (`'byps'`); `address` `juceStringHash64(hostKey)`; `identifier` the hostKey; `aaxId` `ParameterOptions::aaxId` or the hostKey. Under `JUCELegacyIndex` `hostId`, `address` and `aaxId` are the entry's index among all entries (non-automatable included, as JUCE counts), the identifier still the hostKey. In either JUCE scheme the bypass entry, declared or added, has `aaxId` `"MasterBypassID"` (`juceAAXBypassId`) and the added bypass `listedInAU` false, since a JUCE AU and AUv3 list no wrapper bypass; its state key stays `__bypass`. An explicit `hostId` wins in every scheme. `setIdentity`'s debug checks: no two addresses alike, an explicit host id below 2^31 unless unmasked, and under a JUCE scheme JUCE's own (`checkForDuplicateParamID`, `checkForDuplicateTrimmedParamID`, `checkForDuplicateGroupIDs`): unique host keys, AAX ids of at most 31 characters (`juceAAXMaxIdLength`, counted in code points) and unique once truncated to 31, unique group ids. The constructor checks host-id collisions only, so a plugin whose list is built before the wrapper names its scheme does not trip the 2^31 check. `juceVst3ProgramId` (`'prst'`) is reserved for factory presets. The list holds pointers into the group, which must outlive it. Parameters are not Miro fields: there is no `reflectValue` for `Parameter`, so one placed in a `MIRO_REFLECT` list is a compile error, pinned by a `static_assert` in `Tests/ParameterTests.cpp`.
  - **State.** `ParameterGroup::reflect` is the only way a parameter reaches a document: each leaf under its id, each named child group as a sub-object. A save writes a number, a choice's name or a bool; a load accepts any of the three (a choice by exact name, then case- and space-insensitively, or by index) and puts the parameter back to its default when its key is missing or means nothing, and a child group whose object is missing back to its defaults. A load assigns into the registered parameters and never rebuilds a container, so a vector of groups survives it. `StateContext` (`Preset`/`Session`) rides through Miro as the `CustomOptions` tag; a `sessionOnly` parameter is written and read only under `Session` and leaves no key otherwise. `State<ParamsT>` (`ParamsT` derives from `ParameterGroup`) is `version` plus `params`; a subclass reflects further members beside them. `version` is the schema this build writes and a load never changes it; the document's lands in `loadedVersion`, for migration code in a `reflect` override under `ref.isLoading()`. Loading is tolerant: a document with no `params` object, or no JSON at all, moves nothing. `loadParams` is the atomic half of a load, safe from any thread, and `deserializeExceptParams` the other half (a flag the base `reflect` checks before `ref["params"]`). Every non-parameter mutation ends in `markChanged()`, which the owner answers with `publish()` on the message thread; it publishes a preset and a session document, and `snapshotDocument(context)` is the published one with the parameters read live, which is how a host saves off the message thread without waiting on it (Plug's `auval -strict -stress` deadlock). `isPublishedDocumentCurrent` compares with `params` erased on both sides, since automation moves them between any two reads.
  - **`Plugin` and `StatePlugin`.** `Plugin : Processor` adds `name()` (pure), `format()` (set by the wrapper just after construction, so valid from `prepare` on, `Unknown` in the constructor), `acceptsLayout()` (default: `acceptsExactly` the declared layout), `latencySamples()`, `tailSamples()`, `processBypassed()` (below), `takeLatencyChanged()`, the state hooks (`saveState`/`loadState` on the message thread, `saveStateWithoutMessageThread`, `isStateSnapshotCurrent`, `loadParameters`, and `loadStateExceptParameters`, whose default loads the whole document for a plugin that cannot split it, and `loadForeignState(const ForeignState&)`, below), `parameters()` filled through the protected `setParameters`, and a `HostEditListener*` the adapter installs: begin/perform/end edit, an optional edit group, `latencyChanged`, `parameterInfoChanged`, `parameterValuesChanged` (many values moved at once outside a gesture: the host re-reads them all; one value the plugin moves reaches every host without it) and `stateChanged` (state besides the parameters changed: the host marks its document modified), message thread only, raised through `notifyHostLatencyChanged()`/`notifyHostParameterInfoChanged()`/`notifyHostParameterValuesChanged()`/`notifyHostStateChanged()`. `createEditor()` returns an `OwningPointer<Editor>`, null by default, and the host then shows `GenericEditor`; it is cheap by contract, since a host may call it only to learn whether one exists, so the view is built lazily. `setParameters` called again after the wrapper re-appends the wrapper's bypass (below) unless the new list brings a bypass of its own. `processBypassed(ProcessContext&) noexcept` runs instead of `process` while the wrapper's added bypass is on and never otherwise: its default writes the main input to the main output through `BypassDelay` at `latencySamples()` (a mono input feeding every output channel, a channel past the input's zeroed), copies each MIDI in bus to the MIDI out bus of the same index up to its capacity and clears every other output; an override is a bypass of the plugin's own (a tail let ring, another route). `Core/BypassDelay.{h,cpp}` is that delay, a member of `Plugin` the wrapper reaches as a friend: a ring per main input channel of `delay + maxBlock` samples, `prepare` and `ensureDelay` (grows only, starting silent) off the audio thread under a `PrimitiveSpinLock` the audio thread only `tryLock`s, so a block that finds a resize under way is silent rather than waiting; `push` (input into the ring, for a processed block, so a bypass turned on later starts from the input of `latency` samples ago), `process` (push, then read `delay` back, in place safe, a delay past the ring clamped, before any `prepare` a plain copy) and `clear`, all allocation-free. It grows on the message thread through the private `fitBypassDelay()`, from two places: `notifyHostLatencyChanged()`, before telling the listener, and `PluginWrapper::takeLatencyChanged()`, which every adapter's latency check (VST3's, AU's, AUv3's and AAX's `notifyHostIfLatencyChanged`) calls on the message thread in place of the plugin's own `takeLatencyChanged()`, so a latency that moved with no notification (a parameter, say) is caught there, before the host is told; until then, or wherever the check ran off the message thread, a delay past the ring is clamped to it. `StatePlugin<StateT>` owns a `State`, registers its parameters, routes every save and load through it and republishes on `markChanged`, then raises `notifyHostStateChanged()` unless the change is a load (`loadState`/`loadStateExceptParameters` set a flag around the deserialize, since a load the host asked for must not mark its document modified). Both documents are published, so a `StatePlugin` never marshals a save.
  - **Foreign state.** `ForeignState {origin, bytes, context, bypass, program}` (`Core/Plugin.h`) is a document another framework's build of the plugin saved, which an adapter hands over when the host's data holds no MakeASound document: `ForeignOrigin` is `JuceVST3`, `JuceVST2Bank`, `JuceAU`, `JuceAUv3`, `JuceAAX` or `JuceStandalone`, `bytes` exactly what that build's `AudioProcessor::setStateInformation` was given (every format's framing off, a view for the call), `bypass` the wrapper bypass the format saved beside them (the VST3 trailer's, the VST2 bank's `'VstW'`) and `program` the VST2 bank's current program. `Plugin::loadForeignState` (message thread, parameters and the rest alike) returns whether the plugin took it, false by default. `StatePlugin` overrides it to call the protected virtual `loadLegacy(const ForeignState&)` (false by default) under the same load flag as a native load, then `markChanged()`, so the state republishes and the host is not told its document changed: the host asked for the load, and the next save writes JSON anyway. `PluginWrapper::loadForeignState` takes a stamp from the same counter as `loadState`: on the message thread it runs the plugin's hook now and returns its answer; off it, it queues a copy of the bytes there (dropped when a later load of either kind took a stamp, or through the `weak_ptr` past teardown), returns true, and once the plugin took it raises `notifyHostParameterValuesChanged()`, since the host read its values when the call returned. A hook that throws counts as a refusal. When the plugin took a `Session` state carrying `bypass`, the wrapper sets its added bypass from it; a state without one leaves it, as JUCE does, a `Preset` never moves it, and a plugin with its own bypass gets nothing from the wrapper and reads `bypass` itself (JUCE wrote the trailer's only for a plugin with no bypass parameter, whose value is otherwise in the plugin's own bytes).
  - **`Description.h`**: `ModuleDescription {vendor, url, email, version, manufacturerCode, plugins}`, `PluginDescription {name, version, category, subcategory, aaxCategory, pluginCode, create}`, `FourCC`, `Category {Effect, Instrument, MidiEffect}` and `AAXCategory`, Pro Tools' categories SDK-free (`Default`, `EQ`, `Dynamics`, `PitchShift`, `Reverb`, `Delay`, `Modulation`, `Harmonic`, `NoiseReduction`, `Dither`, `SoundField`, `Effect`, `Instrument`; `Default` is `Instrument` for `Category::Instrument` and `MidiEffect` and `Effect` otherwise). `ModuleDescription::version` is the AU bundle's `CFBundleVersion`, which macOS keys its component cache on, so it must move whenever the components do, and the AAX package version; `manufacturerCode` is the AU manufacturer, the AAX `ManufacturerID` and part of every VST3 class id, `pluginCode` the AU subtype and the AAX `ProductID`. `describeModule()` is declared here and defined exactly once per binary, in the plugin's TU; for the tests that is `Tests/PluginTests.cpp`.
  - **Identity** (Stage 10 E, WP10.19/20/17). `PluginDescription` also carries `idScheme` (`IdScheme {MakeASound, JUCE, JUCELegacyIndex}` from `Parameters/ParameterIdentity.h`, MakeASound by default), `juce` (`JuceSettings`, JUCE 8.0.12's per-binary settings with JUCE's defaults: `studioOneCompatibleParameters` true, `forceLegacyParameterAutomationType` false, `vst3CanReplaceVst2` true as `juce_audio_plugin_client.h` defaults it though JUCE's CMake example sets 0, `pluginName` (`JucePlugin_Name`, the name when empty) and `vstUniqueId` (`JucePlugin_VSTUniqueID`, the code when unset); `JUCE_FORCE_USE_LEGACY_PARAM_IDS` is `JUCELegacyIndex`), and overrides that win over any scheme: `vst3ClassId` (`Vst3ClassId`, the four words `FUID` takes), `auType`, `aaxEffectId` and `aaxNativeId` (`AAXNativeIdFn` over `AAXStems {inputChannels, outputChannels, index}`, the hook JUCE calls `getPluginIDForMainBusConfig`). Per plugin and on the description, since JUCE's settings are per binary, a module may hold a port beside native plugins, and a VST3 factory names its classes before any instance exists. `Core/Identity.{h,cpp}` computes from it: `parameterIdentityFor` (`ParameterIdentity {scheme, juceStudioOneMask}`, what `PluginWrapper` applies), `makeASoundVst3ClassId` (`FUID(mfr, code, 'VST3', 0)`, the factory's under MakeASound's scheme), `vst3ClassIdFor` (override, else under a JUCE scheme `Compat::juceVst2ClassId` with `vst3CanReplaceVst2` and `Compat::juceVst3ClassId` without, else MakeASound's), `vst3ClassIdBytes(id, TuidLayout {Plain, COM})` (the TUID bytes; an adapter passes the words to `FUID` and needs neither, since JUCE's Windows byte swaps are exactly the COM layout of the same words), `aaxNativeIdFor` (hook, else JUCE's `'jcaa'` under a JUCE scheme, else code plus index) and `aaxEffectIdFor` (override, else the bundle id under a JUCE scheme as `JucePlugin_AAXIdentifier` defaults, else `<bundle id>.<code>`). Every adapter and the standalone pass `parameterIdentityFor` to their wrapper; the VST3 factory reads `vst3ClassIdFor`, the AU and AUv3 plists and factories `auType` through `componentInfoFor`, and the AAX adapter `aaxNativeIdFor` and `aaxEffectIdFor` (each format's bullets say how).
  - **`PluginWrapper`** (`loadForeignState` is under "Foreign state" above) owns the `Plugin` and its `ProcessContext` and is the per-block pipeline every adapter shares; an adapter translates its host's types into calls here and never calls the plugin's `process` itself. The constructor takes the `PluginFormat` and the plugin's `ParameterIdentity` (default MakeASound's; every adapter passes `parameterIdentityFor(description)`), applied through the private `Plugin::setParameterIdentity` after the added bypass, and kept so a list `setParameters` sets again takes it too. One block, in order: `setNormalizedParameter`/`setParameterByHostId`, `setPlayhead`, `clearMidi` + `pushMidiIn` + `sortMidiInByOffset` (stable), `bindInput` and `bindOutput` per bus, `process()`, then the adapter drains `midiOut()`. `bindOutput` decides per channel: a channel with a matching input channel gets a copy of it, or nothing when the host aliased the two, and a channel past the input's width is zeroed; per channel, because zeroing an output that aliases an input would wipe that input. `process()` clears MIDI out, runs the plugin under `ScopedNoDenormals` and then detaches every audio bus (zero channels, zero samples), so a bus the adapter does not bind next block reads empty instead of last block's host pointers. Every audio-thread member is `noexcept` and allocation-free, and an out-of-range bus or parameter index is a no-op; `pushMidiIn` on a full bus drops the event and returns false. `holdParameter`/`releaseParameter` count a plugin-side gesture, and while one is open `setNormalizedParameter`, `setParameter` and `setParameterByHostId` drop the host's write: the editor sets the `Parameter` directly and reports through `HostEditListener`. `saveState` on the message thread asks the plugin directly (asserting its snapshot is current); off it, it returns `saveStateWithoutMessageThread` and only marshals and waits when that is empty, with a throwing `saveState` handed back through the promise rather than hanging the caller. `loadState` applies `loadParameters` inline and `loadStateExceptParameters` on the message thread (inline when already there), so a host write landing in between survives. Each load takes a stamp from an atomic counter; the deferred half runs only if no later load was taken, and reaches the plugin through a `weak_ptr` so one queued past teardown drops. The wrapper must be destroyed on the message thread (asserted), where a running deferred load would otherwise hold a freed plugin. `ProcessContext::paramChanges` is still empty: adapters write parameters before the block.
    - **The added bypass.** An effect with no bypass of its own gets one, so every host's bypass control reaches every effect with no adapter code: when the plugin's `bypassIndex()` is -1 and its *declared* layout has an input bus, the constructor (before sizing the hold counts) has the plugin add a `BoolParam` "Bypass" (`.id = "__bypass"`, `.bypass = true`, `.sessionOnly = true`), owned by the `Plugin` and appended through `ParameterList::addHostBypass`, so it is the last entry, no other index moves, and every adapter reads it from `parameters()` as `Entry::bypass` like a declared one: VST3's one `kIsBypass` entry, AU's `kAudioUnitProperty_BypassEffect`, AUv3's `shouldBypassEffect`, AAX's master bypass (`describeEffects` describes the plugin unwrapped, so it asks the static `PluginWrapper::addsBypass(plugin)` for `CanBypass`). Its host id is `hostIdFor("__bypass")` (`0x54D1526F`, clear of the VST3 MIDI shadow range). It is decided once, on the declared layout, so the list a host read never changes under it; a layout negotiated later with fewer input channels bypasses what it has. An instrument (no input bus) and a plugin with its own bypass get nothing and run as before: Gain keeps its own, the Synth has none. `process()` reads it per block: steady and off, the main input is `push`ed into the delay and the plugin's `process` runs; steady and on, `processBypassed` runs instead; across a toggle a 10 ms crossfade (`fadeStep` per sample, set in `prepare` from the rate) runs both, the plugin on the host's buses and `processBypassed` on copies of every input bus in scratch buses (`fadeInputs`/`fadeOutputs`, one per bus at `maxBlockSize`, the host's bindings set aside in `hostInputs`/`hostOutputs`), the side being faded to running last so its MIDI out is the block's, and every output bus mixed per sample; a block the scratch cannot hold (longer than prepared, or a bus count `prepare` did not see) switches at once. `prepare` sizes the delay to the main input's channels and `latencySamples()` after the plugin's own `prepare`, and starts the mix at the parameter's value; `reset()` snaps the mix to it and silences the delay. All of it is allocation-free on the audio thread (`Allocations/pluginWrapperBypassedBlockIsOffTheHeap`). **State:** a `Session` save puts `"__bypass": <bool>` at the top of a JSON-object document (an empty document becomes `{"__bypass": ...}`, so a plugin that saves nothing keeps its bypass; Miro's printer reorders the keys); a load parses the document, sets the bypass from the key under `Session` (off when it is missing, as for any session-only parameter), and hands the plugin the document with the key taken out (empty when nothing else was in it), so the plugin never sees it; a `Preset` neither writes nor applies it, and a document that is not a JSON object passes both ways untouched.
  - **`Editor.h`**: `Editor` is what a plugin shows, one eacp view the standalone puts in its window and the VST3 and AU views embed: `view()` (an `eacp::Graphics::View&`, built on first call at the latest and stable for the editor's lifetime), `initialSize()` (`EditorSize`, 400×300 by default), `constraints()` (`EditorConstraints {resizable, minimum, maximum, aspectRatio}` in points, default not resizable, `{1, 1}` to `{16384, 16384}`, ratio `{0, 0}`, which locks nothing; only the ratio's proportion is read), and `onAttached()`/`onRemoved()` as the view goes into a window or comes out of one. `EditorConstraints::constrain(proposed)` (`Editor.cpp`) is the one rule every format applies: each side clamped, and with a ratio the proposal projected onto it, the minimum winning when bounds and ratio admit no size; every host opens the editor at `constrain(initialSize())`. `EditorHost` is whatever shows it (the standalone's window, a VST3 `PlugView`, the AU Cocoa view): `resizeEditor(EditorSize)` (true when the host took the size) and `drawsResizeHandle()`. Every format calls `setHost(this)` before `onAttached()` and `setHost(nullptr)` after `onRemoved()`, so `host()` is valid from `onAttached()` on; `canRequestResize()` is a host and `resizable`, and `requestResize(size)` constrains the size and hands it to the host, false when it cannot or the host refused. Non-copyable, message thread only. A plugin's editor may wrap a `WebView` (`Plugin/Web/`); the host-side UI never does.
  - **`Plugin/Realtime/`**: `MessageThread.{h,cpp}` is `isMessageThread()`, `callOnMessageThread()`, the reclaimer, and for a format loaded into a host `adoptHostMessageThread()` (marks the calling thread as eacp's main one when the code lives in a DLL, `eacp::Platform::isDLL()`; a no-op in an executable, idempotent) and its inverse `releaseHostMessageThread()` (eacp's `detachCurrentThreadAsMain`: the message-only window and its class, the deferred-call scheduler thread and the queued calls go, for the module's exit before the host unloads it), `messageLoopFd()` and `pumpMessageLoop()` (the descriptor a host run loop watches and one non-blocking pass of eacp's loop, defined in `MessageThread-Linux.cpp`; `MessageThread-Default.cpp` answers -1 and does nothing, and `Plugin/CMakeLists.txt` picks one), and the `MessageThread*.cpp` TUs are the only ones in `MakeASound` or `MakeASoundPlugin` that include eacp. `RealtimeSwap<T>` hands a heavy object from the message thread to the audio thread with two atomic slots: `publish(args...)` builds one into `pending` (freeing any the audio thread never took), `currentForBlock()` takes it and moves the old one into `retired`, and a process-wide reclaimer sweeps every registered swap's `retired` on the message thread every 250 ms.   - **`Plugin/UI/`** — the `MakeASoundPluginUI` target (links `MakeASoundPlugin` and `eacp-ui` PUBLIC), the eacp-ui pieces every format shares, so VST3's and AU's views link it without the standalone's device and window code. Edits write the `Parameter` directly and report begin/perform/end through the plugin's `HostEditListener` when there is one (a combo or checkbox change is a whole gesture). `onAttached()` shows a `ResizeGrip` when `ResizeGrip::isWantedBy(editor)` (it can request a resize and its host does not draw a handle, which today is the AU view alone), `onRemoved()` hides it. `ResizeGrip` (`ResizeGrip.{h,cpp}`) is Plug's bottom-right handle, an 18-point eacp view an editor adds as its view's last child at `cornerOf(bounds)`: two-tone diagonals, drawn and hit-testable only while `canRequestResize()`, and a drag asks `requestResize` for the parent's size at `mouseDown` plus the pointer's travel since, never accumulating requests, so a host that answers differently does not make it drift. Message thread only.
  - **`Plugin/Web/`** — the `MakeASoundPluginWeb` target (`ParameterApi.cpp`, `WebEditor.cpp`; links `MakeASoundPluginUI` and `eacp-webview` PUBLIC), built where both exist, which is where eacp has a native web runtime (macOS, iOS, Windows), skipped with a status line elsewhere; namespace `MakeASound::Web`. `ParameterApi` is the Miro API a page drives the parameters through, by id: commands `getParameters()` (`WebParameters`, a list of `WebParameter {id, name, label, normalized, text, steps, choices, automatable}`), `beginEdit`/`endEdit(WebParameterId)` and `edit(WebParameterEdit {id, normalized})`, event `values` (`WebParameterValues {changed}`), each list and bare id inside a reflected struct because Miro's TypeScript codegen emits broken types for a bare `Vector` or string argument.   - **`Plugin/Standalone/`** — two targets, namespace `MakeASound::Standalone`: `MakeASoundStandaloneCore` (`StandaloneHost`, `StandaloneProcessor`, `MidiSender`, `Settings`; links `MakeASoundPlugin` and `eacp-core` PUBLIC, no window) and `MakeASoundStandalone` (`SettingsPanel`, `EditorWindow`, `TypingKeyboard`, `StandaloneApp` and one shell TU, `StandaloneApp-Desktop.cpp` or `StandaloneApp-iOS.cpp`; links `MakeASoundStandaloneCore`, `MakeASoundPluginUI` and `eacp-graphics` PUBLIC).

Pure, with a sink the app points at `injectMidi`.

Device and port ids are per launch, so `resolveConfig(saved, devices, fallback)` re-points each saved side at the device of that name present now (channel span clamped to it, a missing device taking the fallback's side, the rate kept when every device lists it and otherwise `pickCompatibleSampleRate`'s, the block size kept, a config with neither side the fallback) and `resolvePortIds` maps names to today's ids, skipping the missing. `juceSettingsPath(juceName)` is where a JUCE build's standalone named so (its `JucePlugin_Name`) kept its `PropertiesFile` (`juce_audio_plugin_client_Standalone.cpp`): `JuceSettingsPath-Apple.cpp` `<Application Support>/<Name>.settings` (macOS and iOS), `-Windows.cpp` `%APPDATA%/<Name>/<Name>.settings`, `-Linux.cpp` `~/.config/<Name>.settings`, `-Default.cpp` empty, one TU picked in `Plugin/Standalone/CMakeLists.txt`.

It edits a copy of the config and reports it through `onConfigChanged`; the app applies it and answers with `setConfig(engine.getConfig())`, so what is shown is what the engine settled on. `onMidiInputToggled`/`onMidiOutputChanged` report ports; `MidiManager` cannot say which output is open, so the app tells it with `setMidiOutput`. `SettingsPanelOptions::touch` sizes the rows for a finger (56-point rows, 44-point controls, 17-point text), and `addAction(label, onClick)` appends a full-width button below the rows; the iOS shell uses both. Message thread only.

The window's size is not saved in `Settings`. The desktop shell's `EditorWindowHost` is the editor's `EditorHost`: `resizeEditor` sets the window's size and answers whether it took it exactly, `drawsResizeHandle()` true.
    - `StandaloneHost` (`StandaloneHost.{h,cpp}`) is the standalone with no window, and a public API: an app of a plugin's own includes `<MakeASound/Plugin/Standalone/MakeASoundStandalone.h>` (the plugin umbrella, `StandaloneHost`, `SettingsPanel`, `EditorWindow`, `TypingKeyboard` and `GenericEditor`, never `StandaloneApp`), code with no window `StandaloneHost.h` alone over `MakeASoundStandaloneCore`; the app holds the host as its first member and its UI after, and calls `start()`. Members, in construction order: `deviceManager`, `midiManager`, `sender`, `pluginWrapper` (`PluginFormat::Standalone`, the identity `parameterIdentityFor` of the module's first plugin or, for the plugin-and-path constructor, an optional last `ParameterIdentity` argument, so the list is the one every format sees, though nothing here reads a host id; no `HostEditListener`, since there is no host), `processor`, `audioEngine`, the settings path, the JUCE build's settings path, the default `Preset` document, the fallback config, the open MIDI output's id and the settings read at construction. Construction captures the default state and loads the plugin state from the settings file through `loadState(…, Session)` (`resetPlugin()` reloads the captured default as a `Preset`, leaving session-only parameters alone); when the settings file gave nothing (missing, blank or not an object), it imports the JUCE build's instead: `Compat::juceStandaloneState` of that file to `loadForeignState` as `JuceStandalone` (`Session`), its audio and MIDI setup not read, nothing thrown; the next save writes the native file, so the import happens once; `start()` re-opens the saved MIDI ports by name and starts the engine on `resolveConfig` of the saved config (or `fallbackConfig()`, the default output config for every layout: an instrument then asks for no microphone, and an effect's input is only ever one the user picked, because the default microphone into the default speakers is a feedback loop). Until `start()` a save keeps the file's own stream and ports. `applyConfig`, `setMidiInputOpen`, `setMidiOutput` (stopping the `MidiSender` around the open), `resetPlugin` and `resetAudioAndMidi` (every port closed, the fallback config) each save at once, and the destructor saves once more; a UI reads back `config()`, `openMidiInputs()` and `midiOutput()`. `injectMidi`, `createEditor()` (null when the plugin has none), `plugin()`, `wrapper()`, `busLayout()`, `hasMidiInput()`/`hasMidiOutput()` and `devices()`/`midi()`/`engine()` for the lists are the rest.       - `StandaloneApp-Desktop.cpp` (macOS, Windows): members `typing`, `editor` and `editorWindow`, `panel` and `settingsWindow`, `keys`, `editorHost`.       - `StandaloneApp-iOS.cpp`: no menu bar and one window, so one screen, a `Screen` view inside the safe area: a 56-point bar (the plugin's name and a `Settings` button, or `Audio / MIDI Settings` and `Done`) over either the editor or the settings panel.   - **`Plugin/VST3/`** — the `MakeASoundVST3` target (links `MakeASoundPlugin` and `vst3sdk` PUBLIC, and with the view `MakeASoundPluginUI` and `eacp-graphics` PRIVATE), namespace `MakeASound::VST3`. Every TU includes `VST3Common.h` first: it includes `vstsinglecomponenteffect.h` before any other SDK header, because that header renames `IEditController::setState`/`getState` to `setEditorState`/`getEditorState` while it includes `ivsteditcontroller.h` and an earlier include defeats the rename, which is also what makes the unity build safe. No adapter header includes an eacp header (`PlugView.h` forward-declares `EmbeddedView`).
    - `Adapter` is the one class per plugin: `Vst::SingleComponentEffect` (component, processor and controller in one object) plus `IMidiMapping` and `HostEditListener`, owning a `PluginWrapper` built with `PluginFormat::VST3` and the `ParameterIdentity` the factory passes (`parameterIdentityFor(description)`, the constructor's second argument, MakeASound's by default) and driving it in the documented order, never calling the plugin's `process`. A `ParamID` is the entry's `hostId`, looked up with `indexOfHostId`: FNV-1a of the id path under MakeASound's scheme, JUCE's `String::hashCode` of the `hostKey` (masked to 31 bits unless `studioOneCompatibleParameters` is off, then any 32-bit value, nothing in the adapter assuming less) and `'byps'` for the added bypass under `JUCE`, the index under `JUCELegacyIndex`. Under MakeASound's scheme only `isHostExposed` (automatable) entries are registered; under a JUCE scheme every entry is (`ParameterList::isRegistered`), a non-automatable one without `kCanAutomate`, as JUCE's wrapper publishes it (`juce_audio_plugin_client_VST3.cpp`'s `Param`), its gestures reaching the host like any other (WP10.9 is not done for the native scheme). Each is a `ProxyParameter` (`HostParameters.{h,cpp}`) that converts and formats through the MakeASound `Parameter`, `kCanAutomate` from `Entry::automatable`, `kIsBypass` set on the `bypassIndex()` entry alone, and `getParamNormalized` reads the wrapper live. JUCE's `'prst'` program parameter (WP10.12) and its MIDI CC parameters are not made. `prepare` runs in `setActive(true)`, after the bus arrangements are final; `setBusArrangements` goes through `PluginWrapper::setLayout`; a `process` before the first activation writes silence. Latency changes reach `restartComponent(kLatencyChanged)` through a compare-exchange on the last figure the host fetched, on the message thread.
    - **Plugin-side values** reach the host through `data.outputParameterChanges`: `lastPluginValue` holds, per plugin index (relaxed atomics), the normalized value the host last heard of, and at the end of every `process` (the zero-sample flush included, not before the first activation) `emitParameterChanges` adds one point at offset 0 for each exposed parameter whose value moved since, taking the new value as the baseline; a held parameter's move only moves the baseline, since its gesture reports through `performEdit`. A host value never comes back: a queue point and `setParamNormalized` take the plugin's value after the write (a choice's snapped form included) as the baseline, as does `performParameterEdit`. Allocation-free on our side. `parameterValuesChanged` takes every value as the baseline and sends `restartComponent(kParamValuesChanged)`, marshalled to the message thread as the latency is, and `stateChanged` calls `IComponentHandler2::setDirty(true)` (queried off `componentHandler`, marshalled the same way).
    - **State** is one document through `IComponent::getState`/`setState` and the wrapper's `saveState`/`loadState`: a `Session` unless the stream's `IStreamAttributes` names a state type other than `kProject` (then a `Preset`); the controller's `getState`/`setState` stay `kNotImplemented` and `setComponentState` reads nothing. `readAll` (`Stream.{h,cpp}`) reads in 4 KiB reads until one delivers nothing, or fewer bytes than asked with a failing status (a read that delivered counts whatever its status, as Wavelab answers), takes `ISizeableStream`'s size only as a reservation below 100 MiB (some hosts report junk, Cubase 9 a wrong size) and gives nothing for a stream past 2^31 - 1 bytes, as JUCE does (`VST3.cpp` ~2960-3024). A stream that is a JUCE build's session (`isJuceState` in `Adapter.cpp`: not JSON, and a VST2 bank, the private-data trailer JUCE's wrapper always appends, or a bare `copyXmlToBinary` blob) goes to `PluginWrapper::loadForeignState(Compat::juceVST3State(bytes, context))`, which strips the bank and trailer and carries the trailer's or `'VstW'` header's bypass; anything else to `loadState`, so a plugin's own non-JSON document still loads natively. `setState` ends as the bulk call does either way: every value as the baseline, `kParamValuesChanged` (marshalled when the host loads off the message thread, and raised again by the wrapper's `parameterValuesChanged` once a foreign load queued off it has run), then the latency check. The next `getState` writes the native JSON; nothing writes JUCE's framing. No exception crosses the ABI.
    - **MIDI CC** arrives through `IMidiMapping` onto hidden shadow parameters, registered whenever the layout has a MIDI input bus: 16 channels × 131 controllers (CC 0–127, aftertouch, pitch bend, program change) per bus for up to 16 buses, id `0x7FFF0000 | bus << 12 | channel << 8 | controller`, below 2^31; queue points become `MIDI::Event`s at their offsets (`Conversion.{h,cpp}`). A plugin parameter whose host id lands in that range wins (its shadow is not registered), and a debug build asserts on it under MakeASound's scheme and only prints it under a JUCE one, whose hashes a port cannot move. Notes, poly pressure, SysEx and legacy CC events convert both ways.
    - `Factory.{h,cpp}`: `makeFactory(module)` is a `CPluginFactory` listing every plugin, class id (`classIdFor`) `FUID` of the four words `vst3ClassIdFor(module, description)` gives (`Core/Identity.h`): the description's `vst3ClassId` override, else under MakeASound's scheme `FUID(manufacturerCode, pluginCode, FourCC("VST3"), 0)` (Plug's derivation, so a plugin moved from Plug is the same class to a DAW; never change it once shipped), under a JUCE scheme with `juce.vst3CanReplaceVst2` (JUCE's default) JUCE's VST2 id (`'VST'`, the VST2 unique id, nine lowercased name characters), which is the class id itself in JUCE (`getVST3InterfaceId`), so a host replaces the VST2 plugin with it, and without it `FUID(0xABCDEF01, 0x9182FAEB, manufacturer, code)`. JUCE exposes `IPluginCompatibility` only for `JUCE_VST3_COMPATIBLE_CLASSES`, so the factory does not. No `kDistributable` flag. `EntryPoint.cpp` (`GetPluginFactory` over `Steinberg::gPluginFactory`) is compiled into each module, never into the static target. The factory's create function and `initialize` both call `adoptHostMessageThread()`, and `EntryPoint.cpp` registers a `Steinberg::ModuleTerminator` that calls `releaseHostMessageThread()` from `ExitDll`/`bundleExit`/`ModuleExit`: a host scans a plugin, unloads the module and loads it again for the first instance, and eacp's message-only window (its procedure in our image) would otherwise outlive the code it dispatches into, which is how pluginval crashed on Windows at "Open plugin (cold)".
    - **The view.** `createPlugView(owner, plugin)` (`PlugViewFactory.h`) is defined twice, by `PlugView.cpp` where the UI tier exists and by `NoPlugView.cpp` (null) where it does not, the choice made inside the target at link time rather than by a registering initialiser. `PlugView` is a `CPluginView` + `IPlugViewContentScaleSupport` over `eacp::Graphics::EmbeddedView` showing `createEditor()` or `GenericEditor`, holding an `IPtr` to the adapter so the plugin outlives it. The editor lives as long as the view; the embedding only between `attached` and `removed`, with `onAttached()`/`onRemoved()` around it. Platform types: `NSView`, `HWND`, `X11EmbedWindowID`. A `ViewRect` is in points on macOS and in pixels (points × the host's content scale) elsewhere; `getSize` reports `constrain(initialSize())` until the host sizes the view, `canResize` is `constraints().resizable`, `checkSizeConstraint` converts the host's rect to points through `rectScale()`, constrains it and writes it back (the base class's answer for a fixed editor), and key events are left to eacp's own view. `PlugView` is the editor's `EditorHost` from construction to destruction: `resizeEditor` hands the rect to `IPlugFrame::resizeView` (false with no frame or a refusal) and, since the SDK lets an accepting host skip `onSize` when it judges the size unchanged, applies it through `onSize` itself when no `onSize` arrived during the call (a counter, as JUCE does); `drawsResizeHandle()` is true, so no grip is drawn.
    - **The host's run loop.** `HostRunLoop.h` is `attachHostRunLoop(FUnknown*)`, an owned `HostRunLoop` that pumps the message loop for as long as it lives, or null when the context offers no run loop. `HostRunLoop-Linux.cpp` registers an `IEventHandler` for `messageLoopFd()` with the host's `IRunLoop` and calls `pumpMessageLoop()` when it is readable; `HostRunLoop-Default.cpp` always returns null.     - **Platform code is split by TU, as eacp does, never by `#if`**: `PlugView-{macOS,Windows,Linux}.cpp` define `PlugView::nativeViewType()` (the type `attached()` accepts: `NSView`, `HWND`, X11 window id), `rectScale()` (1 on macOS, where a `ViewRect` is in points; the content scale elsewhere, where it is in pixels) and `applyContentScale()` (`setPixelsPerPoint` off macOS, nothing on it), and `Plugin/VST3/CMakeLists.txt` compiles one of each pair.
  - **`Plugin/AU/`** — three targets. `MakeASoundAUDescribe` (`ComponentType.cpp`, `HostParameters.cpp`, `Plist.cpp` and `ViewPlacement.cpp`, linking `MakeASoundPlugin`, AudioToolbox and CoreFoundation PUBLIC, C++20, SDK-free) is built on every Apple platform, iOS included, since the AUv3 adapter shares it; the other two, macOS only, when `TARGET ausdk`. An `__attribute__((destructor))` function cannot do it instead, since dyld registers one when the image loads and so runs it after the image's function-local statics are gone: once `RealtimeSwap`'s reclaimer had started the scheduler, auval aborted at exit locking its destroyed mutex.
    - **Parameters.** An `AudioUnitParameterID` is the parameter's 31-bit host id, looked up with `indexOfHostId`, so `Globals()` runs in map mode; `PostConstructor` writes every exposed id with the plugin's value, so no `SetParameterRT` ever inserts on the render thread, and `SetParameter` is overridden to refuse a global id that is not exposed (`kAudioUnitErr_InvalidParameter`), so the SDK's map never grows behind it. Only `isHostExposed` entries exist to the host: `GetParameterList` returns them sorted by host id and then, stably, by `versionHint` (`parameterListOrder`, JUCE's `AU_1.mm` order, computed once into `listOrder` at construction), because Logic and GarageBand automate an AU parameter by its index in that list, so a parameter added with a higher hint never moves an older one; the constructor asserts once per process (JUCE's `validateParameter` check) when an exposed parameter other than the wrapper's added bypass (id `PluginWrapper::bypassStateKey`, hint 0, so it sorts first and stays put) has hint 0 (`firstUnhintedParameter`), and both examples and every AU-hosted test plugin carry hints. `GetParameterInfo` on another id is `kAudioUnitErr_InvalidParameter`, and `HostParameters.{h,cpp}` fills the info (CF name; the plain range and default with the display flag of `curve()` (`DisplaySquareRoot`, `DisplaySquared`, `DisplayCubed`, `DisplayCubeRoot`, whose host maths `AUParameterValueToLinear` matches `toNormalized`, pinned by a case) for a `Linear` or named curve, and 0..1 with the normalized default for `Other` (`publishesNormalized`); no curve is ever `DisplayLogarithmic`, since no `FloatRange` is a logarithm; unit `Boolean` for a bool, `Indexed` for a stepped parameter whose plain steps are the whole numbers from an integral minimum (a choice, an `IntParam`, a float with interval 1), `Generic` otherwise; flags readable, writable, `IsHighResolution`, `HasCFNameString` and `CFNameRelease` on every one, `ValuesHaveStrings` only on a stepped choice or bool, the ones that answer `GetParameterValueStrings`), the value strings for those, and `kAudioUnitProperty_ParameterStringFromValue`/`ParameterValueFromString` through `valueToText`/`textToValue` (clamped, and the current value when the text yields a non-finite number), so a skewed parameter reads right. Every value the host sees (`Globals()`, `SetParameter`, the text properties, `lastHostValue`) is in that space, `toHostValue`/`fromHostValue` converting at each crossing (the adapter's `hostValueOf` and `setFromHost`, and the reconcile, which compares in host space and keeps `lastPluginValue` plain), so for an `Other` parameter `Globals()` and the ClassInfo `data` hold normalized values. `CanScheduleParameters()` is false, since true makes the SDK `push_back` on the render thread: a host write lands in `Globals()` and, unless a gesture holds the parameter, in the wrapper at once, so a save between the write and the render it lands in never has to choose between the host's value and one the plugin moved itself; on the message thread `SetParameter` also checks the latency, as the VST3 adapter's `setParamNormalized` does.
    - **The scheme.** All of the above is MakeASound's scheme, and `AU::ParameterSpace` (`HostParameters.{h,cpp}`: `isListed`, `listOrder`, `firstUnhinted`, `fillInfo`, `toHost`/`fromHost`, `hasValueStrings`/`copyValueStrings` per `AUFlavour::V2`/`V3`) runs exactly that code for it, so its answers are byte for byte what they were. Under a JUCE scheme (`IdScheme::JUCE` or `JUCELegacyIndex`) it is JUCE's AU (`AU_1.mm` `GetParameterInfo`, `addParameters`, `GetParameterList`) through `Compat::juceAUParameterInfo`: the host ids are the entries' (`String::hashCode` of the `hostKey`, or the index); the listed entries are every one with `listedInAU`, a non-automatable one included as `NonRealTime`, and the added bypass none, so `SetParameter` and `GetParameterInfo` refuse `'byps'`, `Globals()` never holds it and `kAudioUnitProperty_BypassEffect` writes the wrapper directly (a gesture still dropping it) with no parameter event; the range is 0..1, or 0..steps for a choice or a bool (an `IntParam` and a stepped float are continuous to JUCE), the default and every value the host sees the normalized one times that maximum, unit `Indexed`, `Boolean` or `Generic`, flags readable, writable, `HasCFNameString`, `CFNameRelease`, `ValuesHaveStrings` on every parameter, `IsHighResolution` unless `forceLegacyParameterAutomationType`, `CanRamp` on a continuous one; value strings only when `v2ValueStrings`, JUCE's count of them, the text of `min(i / maxValue, 1)`. `JUCE` keeps the map-mode `Globals()` and the (hint, host id) list; `JUCELegacyIndex` calls `Globals()->UseIndexedParameters(n)` in `PostConstructor` (the listed entries are indices 0..n-1, the added bypass last and unlisted), answers `GetParameterList` from the SDK's own indexed list and skips the version-hint assert. The adapter has no clumps (WP10.10) or meters.
    - **Reconciliation** is the top of each render, per exposed entry, against two baselines, `lastHostValue` (what `Globals()` held) and `lastPluginValue` (what the plugin held) at the end of the last block. A host value that moved, on a parameter no gesture holds, goes to the plugin through `setParameter`, and both baselines take the result. Otherwise `Globals()` is written back only when the plugin moved on its own or a held parameter's host write must be undone, and then only if it differs. A host value is therefore never overwritten by the plugin's snapped form of it: auval's "Parameter did not retain set value when Initialized" sets off-grid values a stepped parameter snaps and reads them back. `Initialize` pushes `Globals()` into the plugin and seeds both baselines.
    - **Plugin-side values** reach `AUParameterListener`s (Logic's generic view, its automation) from the message thread, never the render thread: when the reconcile writes a value the plugin moved on its own into `Globals()`, on a parameter no gesture holds, it raises that slot's relaxed atomic in `movedByPlugin`, and `ValueTimer` (`Adapter.cpp`, a 30 Hz `dispatch_source` on the main queue, created when anything is exposed, hidden from the header so no dispatch type reaches an Objective-C++ TU including it) runs `postMovedParameters()`: `AUEventListenerNotify(kAudioUnitEvent_ParameterValueChange)` for each raised slot (taken with `exchange(false)`), `PropertyChanged(kAudioUnitProperty_BypassEffect)` for the bypass entry, and the latency check when any moved. The handler reaches the adapter through a target the cancel handler frees, cleared under its mutex by the destructor, so a unit disposed from another thread waits out a running tick. A held parameter's undone host write raises nothing, its gesture reporting its own values. `parameterValuesChanged` mirrors every value into `Globals()` (the next render takes them as host writes of the same values), clears the bits, posts a value event per exposed parameter and the bypass property where there is one, and checks the latency; `stateChanged` posts `PropertyChanged(kAudioUnitProperty_ClassInfo)`.
    - **Gestures** from the editor go out through `AUEventListenerNotify`: begin (`holdParameter` first), a value change after `Globals()->SetParameter` with the plugin's plain value, end (`releaseParameter` last), only for an exposed parameter; edit groups are no-ops. `parameterInfoChanged` posts `PropertyChanged` for `ParameterList` and `ParameterInfo`.
    - **Buses and formats.** `PostConstructor` sets every element to float32 non-interleaved at the declared count and `SetWillAllocateBuffer(true)` on the outputs. The constructor publishes, through `SupportedNumChannels`, the pairs `acceptsLayout` accepts for main-bus counts 1..8 on each side (0 for a side with no bus), from a member vector that outlives the call. A stream format is writable only before `Initialize`, and `ValidFormat` judges an element alone, since hosts set one at a time: main-bus counts must appear on that side of some published pair, other buses must match the declared count. `Initialize` builds the layout from each element's `NumberChannels()` and runs it through `PluginWrapper::setLayout` (`kAudioUnitErr_FormatNotSupported` when refused), prepares at `Output(0)`'s rate (rounded) and `GetMaxFramesPerSlice()`, sizes the per-bus channel-pointer tables and the 16 KiB MIDI packet buffer (only with a MIDI-out bus), and resets. Buffer pointers are taken per render, never in `Initialize`, because `DoInitialize` reallocates after it.
    - **Render** overrides `Render`, not `ProcessBufferLists`. In order: a pending reset (`wrapper.reset()`), `clearMidi()` and the hand-over of the MIDI staged since the last block onto MIDI-in bus 0 under its spin lock, reconcile parameters, `PullInput` per input bus (one that fails binds empty, one with fewer buffers than channels binds what it has and is not used as a matching input), `setPlayhead` from `CallHostBeatAndTempo`, `CallHostMusicalTimeLocation` and `CallHostTransportState` (`Conversion.{h,cpp}`; the sample time is the transport's `sampleInTimeline`, as VST3 reports `projectTimeSamples`, and the timestamp's `mSampleTime` only when the host has no transport callback; `isValid` when any answered), `sortMidiInByOffset`, bind each output with the input of the same index as the matching input when it was fully bound with the same count, `process()` and MIDI out. Outputs follow `AUBase::DoRenderBus`: with one output element bus 0 is `GetBufferList()`, which the SDK already pointed at the host's buffers or prepared; with more, the SDK renders every bus into its own buffers and copies each out when its bus is rendered, so every bus, bus 0 included, is `PrepareBuffer(frames)`, and a host rendering bus 1 first still finds bus 0 written. `DoRender` already refuses an uninitialized unit and too many frames, and disables denormals itself.
    - **Reset** is a real one: `Reset()` raises an atomic flag and calls the base, and the next render runs `wrapper.reset()`, since the SDK does not serialise `Reset` against `Render`. No CC 120 is injected.
    - **MIDI in.** `HandleNoteOn`, `HandleNoteOff` (the SDK already turns a zero-velocity note on into one), `HandleControlChange`, `HandlePitchWheel` (14-bit, normalized), `HandleChannelPressure`, `HandlePolyPressure`, `HandleProgramChange` and `HandleSysEx` (dropped past `MIDI::SysEx::maxBytes`) stage their event at its frame, and `HandleNonNoteEvent` puts CC 120, 121 and 123 back on the control-change path and stages a program change itself, because `AUMIDIBase` diverts all four to handlers with no frame. `MusicDeviceMIDIEvent` may come from a host thread other than the render thread, so, as in JUCE's wrapper, staging is a `MIDI::Buffer` of the adapter's (1024 events, reserved in `PostConstructor`, a full one dropping the event) under a `SpinLock`, which `Render` empties into the wrapper at the top of the block. AU delivers one MIDI stream, so every event lands on MIDI-in bus 0 and no other MIDI-in bus is ever fed. `MIDIEventList` stays at the SDK default, so a host falls back to `MIDIEvent`.
    - **MIDI out**, with a MIDI-out bus only: `kAudioUnitProperty_MIDIOutputCallbackInfo` (a `CFArray` of bus names) and the writable `kAudioUnitProperty_MIDIOutputCallback`, published to the render thread through a `RealtimeSwap` (`publish` in `SetProperty`, `currentForBlock()` once per render). Each render fills a `MIDIPacketList` in the buffer sized at `Initialize`, one packet per event stamped with its sample offset, flushing to the callback when full, and calls it per non-empty bus with the render timestamp.
    - **State** is the SDK's ClassInfo dictionary plus one key, `MakeASoundState`, a `CFData` of the wrapper's `Session` document (`State.{h,cpp}`), restored through `kAudioUnitProperty_ClassInfo` or `kAudioUnitProperty_ClassInfoFromDocument`, which the SDK does not dispatch and Logic uses for a document, so `GetPropertyInfo` answers it (writable, `sizeof(CFPropertyListRef)`) and `SetProperty` routes it to `RestoreState`. Both paths, and every save, are `Session`: AU gives no reliable preset signal on a save. `SaveState` reads the wrapper, which `SetParameter` already wrote, so a host write no render has consumed yet is in the document and a value the plugin moved itself is not undone. `RestoreState` first replaces a dictionary whose `version` (`kAUPresetVersionKey`, the saved-state format's, which the SDK accepts only at 0) is 1, what an `AUAudioUnit`'s own state carries, with a copy carrying 0 (`copyWithStateVersionZero`, `State.{h,cpp}`, the caller's dictionary untouched), as JUCE does; then it runs the base (which checks the codes and restores `Globals()`), then loads the document and mirrors the plugin's values into `Globals()`, or with no document pushes the restored `Globals()` into the plugin, and checks the latency. A dictionary with no `MakeASoundState` but a non-empty `jucePluginState` (`readJuceState`) is a JUCE build's (`AU_1.mm` ~831-923): the base gets `copyWithoutParameterData`'s copy, `data` removed (the JUCE build's parameter ids would otherwise enter map-mode `Globals()`, which never grows) and a `version` of 1 made 0, as JUCE's own `RestoreState` makes it; then the bytes go to `loadForeignState` as `JuceAU` (`Session`) and every value is mirrored into `Globals()` (off the message thread the load runs later and its `parameterValuesChanged` mirrors again). `ClassInfoFromDocument` takes the same path. The next save is the native document. No exception crosses the ABI. Off the message thread the wrapper's save reads the published snapshot, which is why `auval -strict -stress` does not hang here as it did in Plug.
    - **Latency and tail.** `GetLatency()` is `latencySamples()` over the output rate and records the figure; a change, from `latencyChanged`, a parameter edit or a restore, posts `PropertyChanged(kAudioUnitProperty_Latency)` on the calling thread, through a compare-exchange on the last fetched figure so only the caller that moves it notifies (`takeLatencyChanged` is consumed, through the wrapper's, on the message thread only). `SupportsTail()` is true and `GetTailTime()` is `tailSamples()` over the rate. **Bypass:** `kAudioUnitProperty_BypassEffect` (global, a writable `UInt32`) is answered only for a plugin with a `bypassIndex()` (every effect, the wrapper adding one where the plugin has none), and refused otherwise. Reading it is the bypass parameter's normalized value ≥ 0.5; writing goes through `MusicDeviceBase::SetParameter` on its host id and then the wrapper, so a gesture holding the parameter drops it, and reaches an `AUEventListener` as a value change, the SDK posting the property once `SetProperty` succeeds. A host `SetParameter` that flips it on the message thread, and an editor edit of it, post `PropertyChanged(kAudioUnitProperty_BypassEffect)` too. The plugin does the bypassing itself, as Gain does.
    - **The view** is `kAudioUnitProperty_CocoaUI`, answered only when the module has one. `CocoaUI.h` declares `cocoaViewInfo()` (the factory class name and `[NSBundle bundleForClass:]`'s URL, +1, or two nulls) and `adapterProperty` (64000), a read-only global property the size of a pointer that hands back the `Adapter*`. `CocoaUI.mm` defines it, compiled into each module with ARC, its `NSView` and `<view>Factory` (`AUCocoaUIBase`) classes named by `MAKEASOUND_AU_VIEW_CLASS`, because the Objective-C runtime is one per process and every loaded component registers into it; the per-module name is also what makes the adapter property safe, since a view only ever asks a unit of its own binary. `NoCocoaUI.cpp` answers two nulls where the UI tier is not built, the choice being one source file in the module rather than a registering initialiser and `WHOLE_ARCHIVE`. The view shows `createEditor()` or `GenericEditor` in an `eacp::Graphics::EmbeddedView` over itself at `constrain(initialSize())`, `autoresizingMask` sizable when `constraints().resizable` and `NSViewNotSizable` otherwise, `setHost` and then `onAttached()` once embedded, `onRemoved()` and `setHost(nullptr)` on close. Its `EditorHost` (a weak reference to the view) answers `drawsResizeHandle()` false, since Logic gives an AU window no grip, so the editor draws a `ResizeGrip`; `resizeEditor` is Plug's rule: the view resizes itself, and its superview with it when that is the host's plugin container (`isHostPluginContainer`: exactly the view's size and not the window's content view), inside a `CATransaction` with actions off and a re-entrancy flag, then lays out. A host-driven resize needs no code: the mask has AppKit resize the view with its container, unconstrained. On first entering a window it runs Logic's placement: up to 12 attempts 50 ms apart moving the window inside its screen's visible frame (`containedOrigin`), only when `isEditorWindow` says the window exists to hold the editor (at most 80 points wider and 200 taller), since sizing, placing and ordering front land over several run-loop turns and Logic's view service refuses every move; the last attempt shrinks the editor once by what still hangs off the bottom, keeping its proportions (`shrinkToFit`, never below 240 points, through `requestResize`). `MAKEASOUND_AU_VIEW_TRACE` in the host's environment (`launchctl setenv` for a sandboxed host) logs the view chain, the containment and each resize through `NSLog`. That geometry is `ViewPlacement.{h,cpp}` (`ViewFrame`, `ViewOrigin`, the four functions and their thresholds), on AppKit frames and in `MakeASoundAUDescribe` so it is tested without a window. The host owns the view independently of the unit (Logic disposes the unit first), so the view registers a closer (`addViewCloser`, holding it weakly) that the adapter's destructor runs while the wrapper still lives, and its `dealloc` unregisters. Message thread only.
    - **The plist** is written by `writeAudioComponentsPlist` (`Plist.{h,cpp}` in `MakeASoundAUDescribe`), which the module's second export, `MakeASoundAUWritePlist(bundleName, bundleId, executable, outputPath)` (0 on success, no exception escaping), calls with `describeModule()`. `MakeASoundAUPlistGen` (`PlistGen.cpp`, linking nothing of ours) is `<module binary> <bundle name> <bundle id> <executable> <output plist>`: it `dlopen`s the module (`RTLD_NOW | RTLD_LOCAL`, never closed), calls that function and exits non-zero with `dlerror()` or the failure. The plist has `CFBundlePackageType` `BNDL`, signature `????`, the identifier, name and executable, `CFBundleVersion`/`CFBundleShortVersionString` from `ModuleDescription::version`, and `AudioComponents` with one entry per plugin: `type`, `subtype` and `manufacturer` as four-character strings, `name` `"<vendor>: <plugin>"`, `description`, `version` from `versionNumber(PluginDescription::version)`, `factoryFunction` `MakeASoundAUFactory`, `sandboxSafe` true. `writeAppExtensionPlist(module, AppExtensionPlist {bundleName, bundleId, executable, principalClass, hasView}, output)` is the AUv3 `.appex`'s: `CFBundlePackageType` `XPC!`, the same bundle keys plus `CFBundleDisplayName`, and `NSExtension` with `NSExtensionPointIdentifier` `com.apple.AudioUnit-UI` (with a view) or `com.apple.AudioUnit`, `NSExtensionPrincipalClass`, and `NSExtensionAttributes.AudioComponents`, the entries above less `factoryFunction` and plus `tags`. The platform keys (`MinimumOSVersion`, `CFBundleSupportedPlatforms`, `UIDeviceFamily`) are the packaging's. An iOS module can neither be `dlopen`ed nor run on the build machine, so it is run by `<Name>-Describe` (`DescribeMain.cpp`), a host tool linking the plugin's core built a second time for macOS in the `MakeASoundDescribeBuild` sub-build (plan stage 9, WP9.6).

Its headers are Objective-C++ only. The archive defines no Objective-C class: the target property `MAKEASOUND_AUV3_SOURCES` (`AudioUnit.mm` and the view source) lists what each module compiles itself with `MAKEASOUND_AUV3_CLASS_SUFFIX` defined, and `ClassNames.h`'s `MAKEASOUND_AUV3_CLASS(name)` makes `name_<suffix>` (and `MAKEASOUND_AUV3_CLASS_NAME` its string, for a plist's principal class), for the reason the AU view's class is named per module. `AudioUnit.mm` is the subclass `MakeASoundAudioUnit_<suffix>`, a shell holding an `OwningPointer<Adapter>` and forwarding every override; `AudioUnitFactory.h`'s `audioUnitClass()` hands it out, `adapterOf(unit)` is the `Adapter*` behind one (null for any other class), and `createAudioUnit(description, error)` is what an `AUAudioUnitFactory` answers. The same header declares two functions the view source defines, the choice between a view and none made by which source the module compiles, as the v2 view's: `principalClass()` and `supportedViewConfigurations(plugin, configurations)`, which the subclass's `supportedViewConfigurations:` forwards to.
    - `Adapter` (C++, an `HostEditListener`) is the format: `create(unit, description, error)` finds the plugin by the description's subtype under the module's manufacturer (`kAudioUnitErr_InvalidProperty` and a nil unit otherwise), owns a `PluginWrapper` built with `PluginFormat::AUv3` and the plugin description's `parameterIdentityFor`, holds the unit weakly and never calls the plugin's `process`; `create(unit, description, plugin, error)` builds it over a `PluginDescription` of the caller's, which `createAudioUnit(description, plugin, options, error)` (`AudioUnitFactory.h`, the unit class's `initWithComponentDescription:plugin:options:error:`) reaches and the tests use for `Tests/JucePort.h`. Its `AU::ParameterSpace` of the description answers every scheme-dependent question, as v2's does. **Buses** are `AUAudioUnitBusArray`s from the declared layout, float32 non-interleaved at 44.1 kHz until the host says otherwise, named after the layout's buses, the main bus's `maximumChannelCount` 8; `channelCapabilities` is the `[in, out]` pairs `acceptsLayout` takes over 1..8 per main bus (0 for a side with none), as v2 publishes; `shouldChangeToFormat:forBus:` judges a bus alone (a main bus's count on its side of some pair, any other bus its declared count, float32 non-interleaved, never while allocated) before the base class. `allocateRenderResources` (after the base class's) runs `setLayout` on the buses' counts (`kAudioUnitErr_FormatNotSupported` when refused, the base deallocated again), prepares at the first output's rate (rounded) and `maximumFramesToRender`, builds the render state (our own input and output `Buffer`s, the input `AudioBufferList`s, the channel-pointer tables) and captures `musicalContextBlock`, `transportStateBlock` and, with a MIDI-out bus, `MIDIOutputEventBlock`, then resets; `deallocateRenderResources` drops the state.
    - **Render.** `internalRenderBlock` captures the adapter's C++ pointer and nothing else; the host's blocks are held strongly in the render state and called through `__unsafe_unretained` copies, as is the pull block, so no retain, release, Objective-C message, lock or allocation runs there. A block with no state is `kAudioUnitErr_Uninitialized`, one past `maximumFramesToRender` `kAudioUnitErr_TooManyFramesToProcess` (the base class enforces neither). In order: a pending reset, `clearMidi`, `pullInputBlock` per input bus into our own buffers (a missing block or a failed pull binds empty; a host may point the list elsewhere), the event list (parameter and ramp events written before the block, a ramp at its end value, through `setParameter`, so a held parameter drops them; MIDI and SysEx onto MIDI-in bus 0 at their offsets, `Conversion.mm`'s `sampleOffset` clamping into the block and reading `AUEventSampleTimeImmediate + n` as n, `midiEvent` taking a dump by its `F0` whatever its type), the playhead (`readPlayhead`: the musical context's tempo, meter, beat and bar, the transport's flags, position and cycle, the timestamp's sample time without a transport), `sortMidiInByOffset`, bind, `process()`, and every MIDI-out event through the captured block at the block's sample time plus its offset, the bus as the cable, MIDI 1.0 bytes. Outputs: with one, the host's list, a null `mData` given our own buffer (the base class passes null through); with several, the first call at a new sample time renders every bus into our buffers and each call copies its bus out or points it there.
    - **Parameters** are an `AUParameterTree` (`Parameters.mm`'s `makeParameterTree(list, space)`) of the entries the `ParameterSpace` lists, in declaration order (not v2's `versionHint` order: JUCE's AUv3 tree is declaration order too, a tree host addresses a parameter by address or identifier rather than an index, and a sort would tear the groups apart), each named group an `AUParameterGroup` identified by its `EnclosingGroup::identifier` (from `ParameterList::Entry::groups`), each entry an `AUParameter` with its `Entry::identifier` (the v2 bridge hashes the identifier into the `AudioUnitParameterID` a v2 host saves, so it must be as stable as the id), its `Entry::address`, its display name, and the range, unit, flags and value strings the space's `fillInfo` and `copyValueStrings(…, V3)` give it, so a tree value is in v2's host space and the space's `toHost`/`fromHost` convert at every crossing (`treeValueOf`, `plainFromTree`: the observer, the provider, the string callbacks, a render event's value). Every address lookup is `indexOfAddress` (64-bit, a sorted table, allocation-free), then `isListed`. MakeASound's scheme: the exposed entries, the id paths, the 31-bit host id as address, v2's info less `HasCFNameString` and `CFNameRelease`, and the current value as each parameter's first. A JUCE scheme (`AUv3.mm` `createParameter`): every entry but the added bypass (a non-automatable one `NonRealTime`; the bypass is `shouldBypassEffect` alone), the bare `hostKey` as identifier and a group's own id as its, `hashCode64` of the key as address (the index under `JUCELegacyIndex`), JUCE's range with `HasCFNameString` kept, value strings when `v3ValueStrings` (kept under legacy ids, as JUCE's AUv3 keeps them), and the normalized default as each parameter's first value, as JUCE seeds it; the provider answers live either way. The implementor blocks go through the `Parameter`: the observer writes the plugin through `setParameter` (a held parameter drops it and marks it to be undone), the provider reads it, and the string callbacks are v2's `copyTextForValue`/`valueForText`. The tree's cached value hears nothing of a render-thread write or a value the plugin moved itself, so a 30 Hz main-queue timer (`syncTreeFromPlugin`, also run by a load on the message thread) writes every exposed value that moved since the last sync, or whose dropped host write is to be undone, with `setValue:originator:`; a thread-local flag keeps the observer from writing those back, and each host write records the plugin's value so the sync never replaces a host's value with the plugin's snapped form. `AUParameter` rounds an `Indexed` or `Boolean` value itself. Editor gestures leave as `setValue:originator:atHostTime:eventType:` with `Touch`, `Value` and `Release` around `holdParameter`/`releaseParameter`; `parameterInfoChanged` builds a new tree inside `parameterTree`'s KVO and cuts the old one's blocks loose. The destructor (message thread) cancels the timer and does the same to the tree.
    - **State.** `fullState` is a `Preset` and `fullStateForDocument` a `Session`, each `State.mm`'s ClassInfo-shaped dictionary (`type`, `subtype`, `manufacturer`, `version` 0, the saved-state format's that the AudioUnitSDK requires and not the plugin's, so a session the AUv3 saved on an iPad loads in the v2 component on a Mac) plus `MakeASoundState`, the wrapper's document as `NSData`. A load applies through `loadState` and syncs the tree; a dictionary whose codes name another component, or with neither a document of ours nor a JUCE build's, moves nothing. One of this component's with no `MakeASoundState` but a non-empty `jucePluginState` (`readJuceState`; JUCE's AUv3 writes it into `fullState` and so into the base class's `fullStateForDocument` too, `AUv3.mm` ~256-323) goes to `loadForeignState` as `JuceAUv3` in the call's context (a `Preset` for `fullState`, a `Session` for the document), and the tree is synced (off the message thread by the wrapper's `parameterValuesChanged` once the queued load ran). `parameterValuesChanged` runs `syncTreeFromPlugin` at once rather than at the next tick, posts the `shouldBypassEffect` KVO where there is a bypass and checks the latency; `stateChanged` keeps the empty default, since an `AUAudioUnit` has no dirty signal. No exception crosses into Objective-C. `factoryPresets` is empty, `supportsUserPresets` NO, `currentPreset` the base class's.
    - **Latency, tail, bypass, reset.** `latency` and `tailTime` are the plugin's samples over the output rate; `latency` records the figure, and a change (`latencyChanged`, an edit, a host write on the message thread, a load) is posted as KVO on `latency` through the v2 adapter's compare-exchange. `shouldBypassEffect` is the `bypassIndex()` parameter's normalized value ≥ 0.5, and setting it goes through `setParameter` (a held gesture drops it) and the tree; a plugin with none answers NO and ignores the write. A host write or an editor edit that flips it posts KVO on `shouldBypassEffect`. `reset` raises the flag the next render answers with `wrapper.reset()`.
    - **The view.** `MakeASoundAUv3View` (`EmbeddedEditor.mm`; links `MakeASoundAUv3`, `MakeASoundPluginUI` and `eacp-graphics` PUBLIC, `-fobjc-arc -fapplication-extension`) is the half both platforms share: `EmbeddedEditor` builds `createEditor()` or `GenericEditor`, gives `openingSize()` (`constrain(initialSize())`), `attach(nativeView, size, request)` embeds it through an `eacp::Graphics::EmbeddedView` over the controller's view, then `setHost` and `onAttached()`, and registers a closer with the adapter (`Adapter::addViewCloser`/`removeViewCloser`, run first in its destructor, as v2's), `hostResized(size)` hands the embedding a host's size unconstrained, and `close()` (idempotent, also the closer) runs `onRemoved()` and `setHost(nullptr)` and drops the embedding and the editor.   - **`Plugin/AAX/`** — the `MakeASoundAAX` target (`Adapter`, `Conversion`, `Describe`, `Parameters`, `State`; links `MakeASoundPlugin` and `aaxsdk` PUBLIC, and with the view `MakeASoundPluginUI` and `eacp-graphics` PRIVATE; unity under `MAKEASOUND_UNITY_BUILD`), macOS only and built only when `TARGET aaxsdk`, so only under `MAKEASOUND_BUILD_AAX`; namespace `MakeASound::AAX`, inside which the SDK's own namespace is spelled `::AAX::` (`::AAX::Exception::ResultError`). Every adapter TU includes `AAXCommon.h` (the SDK headers it needs) first, and no Avid type reaches a `MakeASoundPlugin` header. The design follows JUCE's and clap-wrapper's AAX wrappers.
    - **The description.** `GetEffectDescriptions` (`EntryPoint.cpp`) adopts the message thread and calls `describeEffects(collection, module, bundleId, packageName)` (`Describe.{h,cpp}`), the bundle id being `moduleBundleId()` (declared in `Describe.h`, defined once per binary: by `EntryPoint.cpp` from `MAKEASOUND_AAX_BUNDLE_ID`, by `AAXTests.cpp` in the tests) and the package name `MAKEASOUND_AAX_PACKAGE_NAME`. It constructs each plugin once to read its layout and bypass and adds one effect per plugin that accepts any stem pair, under the effect id `aaxEffectIdFor(bundleId, plugin)` (`Core/Identity.h`: the description's `aaxEffectId`, else under a JUCE scheme the bundle id alone, as JUCE's `JucePlugin_AAXIdentifier` defaults and its `AddEffect` takes it, else `<BUNDLE_ID>.<pluginCode>`, byte for byte as before; two plugins of one JUCE-scheme module therefore need an `aaxEffectId` each), with its name plus the 31-, 15-, 7- and 4-character truncations Pro Tools picks from, `categoryFor(plugin)` (`aaxCategory`, or the default by `Category`), the `Adapter::create` proc and, where the module has a view, `createAAXView`; then the manufacturer name (`vendor`), the package name and `SetPackageVersion(ModuleDescription::version)` as `major << 16 | minor << 8 | patch`. A module that describes nothing returns `AAX_ERROR_NULL_OBJECT`; an SDK error (`AAX_CheckedResult`) or any other exception comes back as a result code, never across the ABI.
    - **Components and ids.** `stemPairs()` is the append-only list Mono→Mono, Mono→Stereo, Stereo→Stereo, None→Mono, None→Stereo; `layoutFor(declared, pair)` sets the main buses' counts and refuses a pair whose input side does not match whether the layout has an input bus, and each pair `acceptsLayout` accepts is one component: `AAX_eProperty_ManufacturerID` `manufacturerCode`, `ProductID` `pluginCode`, `PlugInID_Native` from `nativePluginId`, which is `aaxNativeIdFor` (`Core/Identity.h`) over the pair's channel counts and index: the description's `aaxNativeId` hook, JUCE's `'jcaa'` derivation under a JUCE scheme, and otherwise `pluginCode` plus the pair's index (MakeASound's own derivation, not JUCE's, which is why the list never reorders), the stem formats, `CanBypass` when `bypassIndex()` is set, `UsesTransport`, `Constraint_Location` `DataModel`, `Constraint_Topology` `Monolithic` and no multi-mono. Gain gets Mono→Mono and Stereo→Stereo, the Synth None→Stereo. Surround and side-chain stems wait for a bus with channel roles.
    - **The algorithm.** `AlgorithmContext.h` is the context struct, packed with the SDK's alignment headers, its field order the ABI: `inputs`, `outputs`, `numSamples`, `clock`, `midiIn`, `midiOut`, `transport`, `privateData`. Each component adds its audio in and out, buffer length, clock, the transport node, a `PrivateData {Adapter*}` block, and the local MIDI input and output nodes only when the layout has that MIDI bus; an unused MIDI field gets a placeholder private-data port instead (as Avid's monolithic template does), since a gap in the context fails with "Algorithm context contains gaps". One `AddProcessProc_Native(processProc)` per component: `processProc` walks its instances and calls `adapter->render(context)` through the private data, which `ResetFieldData` fills with `this`. No packet dispatcher, coefficients, DSP or HDX path.
    - `Adapter` is the data model every plugin ships as: `AAX_CEffectParameters` plus `HostEditListener`, owning a `PluginWrapper` built with `PluginFormat::AAX` and driving it in the documented order, never calling the plugin's `process`. `Initialize` adopts the message thread; `EffectInit` finds the plugin whose `aaxEffectIdFor` is the controller's effect id (`findPlugin(module, bundleId, effectId)`, over the module and bundle id the adapter was built with: `module()` and `moduleBundleId()` by default, another pair through `Adapter(module, bundleId)` for the tests), builds the wrapper with `parameterIdentityFor(description)`, takes the stem formats and sample rate, refuses a layout `setLayout` refuses, prepares at the rounded rate and a maximum block of 1024 (`1 << AAX_eAudioBufferLengthNative_Max`), sizes the channel tables, reserves the MIDI staging buffer, installs itself as `HostEditListener`, registers the parameters and reports `SetSignalLatency`. `module()` is a function-local `describeModule()`.
    - **Render**, per instance: silence before `EffectInit`; the input node's packets through a `MidiParser` (`readMidi`, `Conversion.{h,cpp}`), each message at its packet's `mTimestamp` clamped into the block and a SysEx split across packets assembled, onto a staging `MIDI::Buffer`, sorted; the playhead from the transport node (`readPlayhead`: `GetCurrentTempo`, `GetCurrentMeter`, `IsTransportPlaying`, `GetCurrentNativeSampleLocation`, `GetCurrentTickPosition` and `GetCurrentLoopPosition` over 960000 ticks per quarter, `isValid` when any answered; `barStartPpq` and `isRecording` are not mapped). A block past 1024 samples is rendered in slices of 1024, each with its own `clearMidi`, the staged events inside it shifted to its start, the playhead `advance`d to it, `bindInput`/`bindOutput` over the context's channels offset to it, `process()`, and MIDI out bus 0 posted with `PostMIDIPacket` at the event's offset plus the slice's start (`packetFor`: channel-voice messages only, since Pro Tools routes no plugin SysEx). AAX delivers one MIDI stream, so everything lands on MIDI-in bus 0. Denormals are the wrapper's.
    - **Parameters.** The registered entries (`ParameterList::isRegistered`, shared with VST3: under MakeASound's scheme the `isHostExposed` ones, under a JUCE scheme every one, a non-automatable one as not automatable, as JUCE's `AAX.cpp` ~1764 does) are each an `AAX_CParameter<float>` (`makeParameter`, `Parameters.{h,cpp}`) in normalized units over a linear 0..1 taper, automatable from the entry, its short name added, `numSteps + 1` steps and the discrete type on a stepped one, and an `AAX::DisplayDelegate` that formats and parses through the MakeASound `Parameter`, clamped, text yielding no finite number keeping the current value. `AAX_CParamID` is the entry's `aaxId` (`ParameterList`): under MakeASound's scheme the 31-bit host id as eight lowercase hex digits, byte for byte as before, so an inserted or renamed parameter keeps everyone's automation; under `JUCE` the `ParameterOptions::aaxId` or the hostKey, under `JUCELegacyIndex` the index in decimal, and in either `"MasterBypassID"` for the bypass, declared or added. It is registered as `registeredId(aaxId)`, its first 31 bytes, because the SDK's `AAX_CParameterValue::InitIdentifier` keeps no more (so a JUCE build registered a non-ASCII id of up to 31 code points cut mid-character, and its sessions name it so). `indexOf(id)` binary-searches the registered ids (`byParamId`), allocation-free; the SDK's own `GetParameterByID` builds a `std::string` from the id, so a host write by an id past the library's short-string capacity (22 bytes on libc++) allocates inside the SDK. A host write arrives through `UpdateParameterNormalizedValue`: the base keeps the host's value in the `AAX_CParameter`, and the write goes into the wrapper unless a gesture holds the parameter, with no packet dispatcher. `TimerWakeup` mirrors to the host only the values the plugin moved on its own since the last look (`lastPluginValue`) on parameters no gesture holds, so a value the host wrote and the plugin snapped is never written back; `SetChunk` (but for `'elck'`) and `parameterValuesChanged` mirror every one at once, the latter then checking the latency. `stateChanged` adds one to an atomic count that `GetNumberOfChanges` adds to the base's parameter changes (JUCE's `numSetDirtyCalls`), so Pro Tools marks the session modified for state that is not a parameter.
    - **Gestures** from the editor: `beginParameterEdit` holds the parameter and calls `TouchParameter`, `performParameterEdit` calls `SetParameterNormalizedValue` with the plugin's normalized value, `endParameterEdit` calls `ReleaseParameter` and releases, only for a registered parameter. Edit groups are no-ops and `parameterInfoChanged` has no AAX counterpart in 2.8.1.
    - **Bypass.** With a `bypassIndex()` entry `CanBypass` is set and `GetMasterBypassParameter` names that entry's id; the plugin bypasses itself, as Gain does, or, for an effect with none, the wrapper's added bypass is that entry and `describeEffects` sets `CanBypass` through `PluginWrapper::addsBypass`. Under a JUCE scheme that id is `"MasterBypassID"`, as JUCE's AAX names any bypass, which the base's `Initialize` also filters out of its `'elck'` save and load. An instrument names nothing (JUCE's AAX gives an instrument a `"MasterBypassID"` of its own too; the wrapper does not, so a JUCE instrument's master-bypass automation has nowhere to land).
    - **State** is one chunk, `'MkaS'` (`State.{h,cpp}`): `GetChunkSize` saves the wrapper's `Session` document into a member under a mutex and answers its size, `GetChunk` copies that member (the SDK pairs the two calls; `AAX_ERROR_INCORRECT_CHUNK_SIZE` when it does not fit), `SetChunk` loads it as a `Session`, mirrors every value to the host and checks the latency. `SetChunk` also reads, but nothing lists or writes, the two chunks a JUCE build leaves in a session (`AAX.cpp` ~851-924): `'juce'` (`juceChunkId`, `JucePlugin_AAX_Chunk_Identifier`'s default) goes to `loadForeignState` as `JuceAAX` (`Session`), and `'elck'` (`controlsChunkId`, the SDK's controls chunk: `AAX_CChunkDataParser`'s `0x01010101`, then per value `d_`, the AAX id, a NUL, zeroes to a four-byte boundary and a big-endian double, which over JUCE's 0..1 linear taper is the normalized value as a float, the master bypass left out) goes to the SDK's own `SetChunk`, as JUCE's `SetChunk` leaves it, which sets through the host every registered parameter whose id the chunk names and skips the rest, so it lands under a JUCE scheme and moves nothing under MakeASound's. `'MkaS'` and `'juce'` then mirror every value and check the latency; `'elck'` only checks the latency, since its values come back through `UpdateParameterNormalizedValue`, perhaps later. Any other id is `AAX_ERROR_INVALID_CHUNK_ID`. Only `'MkaS'` is listed, so the next save is the native document; whether Pro Tools hands an unlisted chunk to `SetChunk` is the open check in `plan.md`. `CompareActiveChunk` compares the chunk's `params` object with the live one's, the bypass entry left out as the SDK leaves the master bypass out of its own compare, and answers equal for a chunk of another id, `'juce'` and `'elck'` included. Every save is a `Session`, as in AU, since Pro Tools gives no preset signal; `AAX_eProperty_RequiresChunkCallsOnMainThread` stays false, because the wrapper's off-thread save reads the published snapshot. No exception crosses the ABI.
    - **Latency.** `SetSignalLatency(latencySamples())` from `EffectInit`, and on a change from `latencyChanged`, a host write on the message thread, a gesture, `SetChunk` or `TimerWakeup`, through a compare-exchange on the last reported figure, so only the caller that moves it tells the host. AAX 2.8.1 has no tail query; `tailSamples()` is unused.

- **`DSP/`** — the `MakeASoundDSP` target, its own `CMakeLists.txt`, linking `MakeASound` PUBLIC and nothing else; umbrella `MakeASound/DSP/MakeASoundDSP.h`, namespace `MakeASound::DSP`. Nothing in the library links it: an app or a plugin that wants a processor from it does. `TestSynth` is a `Processor` with `BusLayout::instrument()`: monophonic, last-note priority (a release falls back to the newest note still held), one oscillator (`Waveform::Sine`/`Saw`/`Square`), a linear attack/release envelope, a 20 ms `Smoother` on the output level, and CC 123 as all-notes-off. `Settings {waveform, attackSeconds, releaseSeconds, gain, legato}` is set per block on the audio thread through `setSettings`, which ramps the gain. `process(ProcessContext&)` splits the main output around the main MIDI-in bus's events; `render(Buffer&)` and `handleEvent(const MIDI::Event&)` are the pieces it is made of, public for a host that wants to see each event, and `getCurrentNote()`/`getVelocity()`/`isPlaying()` read the voice. `prepare` reserves the 128-entry note stack, so a block never allocates (`Tests/AllocationTests.cpp` pins it) and `Tests/TestSynthTests.cpp` covers the rest. `Plugins/Synth` is this synth with its settings on parameters and a React editor; `Apps/Synth` is it with an atomic gain, the web page's MIDI log and a release flag the page sets.

- **`Common/`** — `Common.h` re-exports `EA::Vector`/`Array`/`OwningPointer`/`Span` into the `MakeASound` namespace; `Algorithms.h` has small audio-thread-safe helpers.

- **`MiniAudio/`**, **`CoreMIDI/`**, **`WinMIDI/`** and **`ALSA/`** — the backends (namespaces `MakeASound::MiniAudio`, `MakeASound::CoreMIDI`, `MakeASound::WinMIDI` and `MakeASound::ALSA`). Each has a `*-Backend.{h,cpp}` of pure conversion functions and a `*Manager.{h,cpp}` that owns the handle. `MiniAudio::DeviceManager` owns the `ma_device` and the `audioCallback` trampoline that miniaudio invokes; it **de-interleaves** the incoming/outgoing interleaved buffers into two owning `Buffer` scratches, sized at open for the negotiated block, and re-interleaves on the way out (so callers only ever see planar data). miniaudio is the only third-party library left behind either façade; every MIDI backend is the platform's own API.
  - `CoreMIDI::MidiManager` is the Apple MIDI backend. It holds the `MIDIClientRef`, one shared input port that every opened source connects to, one output port, and a per-open-port `InputPort` carrying its `MidiParser`, its SysEx assembly buffer and its `SPSCQueue`. Raw MIDI 1.0 bytes only: `MIDIPacketList` in and out (`MIDIInputPortCreateWithBlock`, `MIDISend`, `MIDIReceived`), so the wire stream reaches `MidiParser` as it arrived rather than through a UMP round trip.
  - **Run-loop thread.** Core MIDI delivers notifications on the run loop that was current when the *process* created its first MIDI client, and keeps that pin after the thread dies. So `NotifyLoop` is a process-wide singleton thread, started on first use and never stopped, on which every client is created, used and disposed — hotplug then works in a CLI with no run loop of its own, and a manager built after an earlier one died still hears it. Where another library got its client in first the pin is theirs; both notification paths still carry whatever arrives.
  - `WinMIDI::MidiManager` is the Windows MIDI backend. One `HMIDIIN` per open input with a `CALLBACK_FUNCTION` callback, one `HMIDIOUT`, and the same per-port `InputPort` (`MidiParser`, assembly buffer, `SPSCQueue`) the Apple one has. Short messages arrive packed into `MIM_DATA`'s dword and are unpacked by status length; a dump arrives through a ring of four 1 KiB `MIDIHDR`s, re-armed with `midiInAddBuffer` from inside the callback — the one WinMM call allowed there. A header handed back empty is `midiInReset` on the way out, not data, so it is not re-armed. Names carry the port index appended, and that name is the whole identity WinMM offers.
  - **No loop thread on Windows.** WinMM has no virtual ports, no hotplug notification and no thread of ours to sweep on, so `openVirtual*` refuse, `PortAdded`/`PortRemoved` are diffed out of each `getInputPorts()`/`getOutputPorts()` against the previous scan, and the receive thread's `QueueOverflow`/`SysExDropped` flags are swept there too — not in `drainMessages()`, which is the audio thread's and `notifyHost` locks. Timestamps are `MIM_DATA`'s milliseconds since `midiInStart` added to a `steady_clock` reading taken at that call, so 1 ms is the resolution of every arrival. Output SysEx goes out through `midiOutPrepareHeader`/`midiOutLongMsg` on a staging buffer sized at open, and `midiOutUnprepareHeader` is the wait that keeps `sendMessage` synchronous.
  - **Two SysEx tiers.** Callback mode delivers a dump of any size up to the port's assembly buffer (`MidiManager::setMaxSysExBytes`, default 64 KiB, allocated at open, never on the MIDI thread); queue mode delivers one only when it fits `MIDI::SysEx::maxBytes` (32). Either drop raises `SysExDropped`. Queue mode hands events over through a per-port `SPSCQueue<MidiInputEvent, 2048>`; a full queue drops the event and raises `QueueOverflow`. Both notifications are raised from a flag the receive thread sets and the run loop sweeps, because `notifyHost` takes a mutex and the MIDI thread may not.
  - `ALSA::MidiManager` is the Linux MIDI backend. One sequencer client (`snd_seq_open`, duplex) with one application input port every subscription lands on and one output port every send leaves by; **opening a port is a subscription** (`snd_seq_connect_from` / `snd_seq_connect_to`), and a **virtual port** is a port of our own — `WRITE|SUBS_WRITE` for a virtual input, `READ|SUBS_READ` for a virtual output — which is why the loopback the tests use is the same on Linux as on Apple. Enumeration walks `snd_seq_query_next_client`/`_port`, naming a port `"<client>:<port> <client num>:<port num>"` and skipping the system client and our own two plumbing ports but not our virtual ones. An event routes to its `InputPort` by `dest.port` when it is a virtual one of ours and by `source` when it came through the shared input port; its bytes reach `MidiParser` raw (a `SND_SEQ_EVENT_SYSEX` fragment as it is, anything else through `snd_midi_event_decode`), so the SysEx tiers and the ignored types are identical to Core MIDI's.
  - **Input thread.** One per manager, blocking in `poll` over `snd_seq_poll_descriptors` plus an `eventfd`, with `snd_seq_event_input_pending(seq, 1)` guarding every `snd_seq_event_input` so a blocking handle never blocks it. It takes no lock and no heap: the open-port list belongs to it, and the host **parks** it (a write to the `eventfd`, an acknowledgement through two atomics) before opening or closing anything, which costs the thread one relaxed load per wake-up. `PortAdded`/`PortRemoved` come from `SND_SEQ_EVENT_PORT_START`/`PORT_EXIT` on the system announce port, pushed into an `SPSCQueue` that a small sweeper thread turns into notifications every 100 ms alongside the dropped/overflow flags — the run loop's job on Apple. The poll timeout is also what ticks the parser's SysEx timeout when a dump stalls.
  - **Timestamps and sends.** A realtime sequencer queue timestamps every input port, and the offset between its clock and `steady_clock` is taken once when the queue starts, so `MidiInputEvent::arrival` is the kernel's stamp on `MidiManager::now()`'s clock; an unstamped event falls back to now. Sends go out through `snd_seq_event_output` + `snd_seq_drain_output` rather than `snd_seq_event_output_direct`, which grows a scratch buffer of its own the first time it is handed a variable-length event; a dump leaves as a run of ≤512-byte SysEx fragments pointing straight at the caller's bytes, so a send of any size is synchronous and allocation-free.

**Default configs:** there is no `getDefaultConfig()` — `getDefaultOutputConfig()` / `getDefaultInputConfig()` / `getDefaultDuplexConfig()` make the direction explicit, because a config that claims an unwanted capture side costs the app a microphone permission on macOS and iOS. `pickCompatibleSampleRate` prefers a device's `currentSampleRate` over its `preferredSampleRate`: re-clocking a shared device moves it under every other app, and asking for a rate it is not on leaves the backend resampling.

**Adding a new file/module:** create `Lib/MakeASound/<Folder>/<Name>.{h,cpp}` (reuse an existing domain folder where it fits) and add `MakeASound/<Folder>/<Name>.cpp` to the source list in `Lib/CMakeLists.txt`. Include siblings in the same folder as `"<Name>.h"` and headers in other folders as `"../<Folder>/<Name>.h"`.

**Device ids:** an id is a slot in a name-keyed registry (`idForDevice`), not a position in the enumeration, so a hotplug does not renumber every device after the one that moved and a cached `DeviceInfo::id` keeps naming what it named. The registry is per-API and `setBackend` clears it.

**Notifications:** every one goes down two paths — `notificationCallback`, delivered immediately on whatever OS thread raised it, and a mutex-guarded queue the host drains with `DeviceManager::drainNotifications()` on its own thread. Keep both fed from `notifyHost`; the queue is what lets a UI react without writing its own marshalling.

**Callback status:** miniaudio's data callback carries no status, so `AudioCallbackStatus` is measured from the callback clock (`getCallbackStatus`): a block arriving more than a period late past a small margin missed its deadline. Keep `lastCallbackUs` in microseconds — the watchdog and this share it, and millisecond resolution is too coarse at small block sizes.

**Dirty-flag flow:** `DeviceManager::openStream` wraps the user callback in a lambda that compares the incoming `AudioCallbackInfo` against `prevInfo` (via the struct's `operator==` on channels/sampleRate/maxBlockSize) and sets `info.dirty = true` on change. Preserve this wrapping when editing `openStream` — the raw backend callback does not set `dirty`.

**Failure handling:** neither the audio path nor the MIDI one throws. `DeviceManager::start`/`setConfig` return an `Error`, and `isRunning()`/`getLastError()` say what happened; `getErrorMessage(Error)` turns one into something a user can read. A machine with no device, or with one that is busy, is an ordinary desktop state — `getDefaultConfig()` leaves a side unset when the machine has nothing of that kind (asking for duplex on a mic-less box fails the whole open), and the miniaudio backend maps every `ma_result` through `getError` instead of raising. Keep new backend code on that path: the recovery worker drives opens from its own thread, where an exception has nowhere to go. The MIDI façade returns `Error` too, and no MIDI backend throws: an `OSStatus`, an `MMRESULT` and a negative errno each go through their backend's `getError`. `ALSA::MidiManager` maps every negative errno through `getError` and silences alsa-lib's own stderr hook (`snd_lib_error_set_handler`) for the length of its open, because a machine with no `/dev/snd/seq` is an ordinary state: `isAvailable()` is false, nothing is printed and every call is a no-op.

**Allocation tests:** `Tests/AllocationTests.cpp` and `Tests/RealtimeThreadAllocationTests.cpp` assert that the real-time paths never reach the allocator, through the shared harness in `Tests/AllocationProbe.h`. The ban is thread-local and covers `free` as well as `malloc`, so what is measured is heap *activity*, not growth. The pure paths are called under a `ScopedSetter`; the threads we don't own (a live audio callback, the platform's MIDI thread — Core MIDI's receive thread on Apple, the ALSA backend's own input thread on Linux) raise and lower the ban from inside their own callbacks and report through an atomic — `ThreadProbe::mark()` runs at the end of the callback, so the window it opens covers that block's tail plus all of the next one. Interposition needs `dlsym(RTLD_NEXT, ...)`, so both files (and the `AllocationsChecker` link) are added to the test target only on Apple and Linux — the condition lives in `Tests/CMakeLists.txt`, not in the sources, and a suite that reports zero because nothing was watching is worse than no suite. Anything new on the audio thread or on the platform's MIDI thread belongs here — the allocations these caught were a `MidiMessage` built and destroyed per delivered message on the way out of a port (now a per-port buffer the callback borrows), `MIDI::Buffer::addFrom` reserving the source's size instead of the merged one, and alsa-lib's `snd_seq_event_output_direct` growing a scratch buffer for a variable-length event (now `snd_seq_event_output` + drain).

## Conventions

- C++20, namespace `MakeASound`; backend code in `MakeASound::MiniAudio`, `MakeASound::CoreMIDI`, `MakeASound::WinMIDI` and `MakeASound::ALSA`, format code in `MakeASound::Standalone`, `MakeASound::VST3`, `MakeASound::AU`, `MakeASound::AUv3` and `MakeASound::AAX`. The one exception to C++20 is whatever links `ausdk`, whose headers need C++23.
- `.clang-format`: Allman braces, 4-space indent, 85-col limit, pointer-left, no tabs, `NamespaceIndentation: None`, `SortIncludes: false` (include order is intentional — don't reorder).
- The `MakeASound` CMake target is a `STATIC` library; sources are listed individually in `Lib/CMakeLists.txt`. It links `Miro` PUBLIC (Miro headers leak through the public data structs) and `miniaudio` PRIVATE, plus whichever MIDI library the platform selected — the Core MIDI frameworks on Apple, `winmm` on Windows, `ALSA::ALSA` + `Threads::Threads` on Linux (every backend is fully hidden behind the façades).
- `MakeASoundPlugin` is a second `STATIC` target, defined in `Lib/MakeASound/Plugin/CMakeLists.txt`, which `Lib/CMakeLists.txt` adds under `MAKEASOUND_BUILD_PLUGIN`. It links `MakeASound` PUBLIC and `eacp-core` PRIVATE. eacp stays inside the `Plugin/Realtime/MessageThread*.cpp` TUs, and no header includes one of eacp's (`Editor.h` forward-declares the view), and no format SDK ever enters the target: an adapter links its SDK on top.
- `MakeASoundDSP` (`DSP/`, linking `MakeASound` PUBLIC) is a `STATIC` target in its own directory's `CMakeLists.txt`, always built, never linked by the library itself.
- `MakeASoundStandaloneCore` (`Plugin/Standalone/`, linking `MakeASoundPlugin` and `eacp-core` PUBLIC) is a `STATIC` target built wherever the plugin core is; it includes eacp-core headers only, and only a standalone links it.
- `MakeASoundPluginUI` (`Plugin/UI/`, linking `MakeASoundPlugin` and `eacp-ui` PUBLIC) and `MakeASoundStandalone` (`Plugin/Standalone/`, linking `MakeASoundStandaloneCore`, `MakeASoundPluginUI` and `eacp-graphics` PUBLIC) are two more `STATIC` targets, each in its own directory's `CMakeLists.txt` and each gated on the eacp target it links existing. A plugin whose editor wants eacp-ui links `MakeASoundPluginUI` itself; only a `<Name>-Standalone` executable links `MakeASoundStandalone`. These do include eacp's UI and graphics headers, which is why they are separate targets: nothing that links only `MakeASoundPlugin` ever sees them.
- `MakeASoundPluginWeb` (`Plugin/Web/`, linking `MakeASoundPluginUI` and `eacp-webview` PUBLIC) is a `STATIC` target built where both exist (macOS, iOS, Windows), linked by a plugin core through `makeasound_add_web_editor`; it records `ParameterApi.h`'s path as `MAKEASOUND_WEB_API_HEADER` for that function.
- `MakeASoundPluginval` (`Plugin/Validation/`, linking `MakeASound` and `eacp-network` PUBLIC) is a `STATIC` target built where `eacp-network` exists on a desktop, linked only by `PluginValidator` and the test target; on Linux `eacp-network` needs libcurl's development package.
- `MakeASoundVST3` (`Plugin/VST3/`, linking `MakeASoundPlugin` and `vst3sdk` PUBLIC) is a `STATIC` target built where `vst3sdk` exists on a desktop (not iOS or Android), with the view TU and `MakeASoundPluginUI`/`eacp-graphics` PRIVATE when those exist and `NoPlugView.cpp` otherwise; it defines `MAKEASOUND_VST3_HAS_VIEW=1` PUBLIC with the view. Its entry, plist, `PkgInfo` and Linux export-map paths are the target properties `MAKEASOUND_VST3_ENTRY`, `MAKEASOUND_VST3_PLIST`, `MAKEASOUND_VST3_PKGINFO` and `MAKEASOUND_VST3_LINUX_EXPORTS`, which `makeasound_add_plugin` reads. Only a `<Name>-VST3` module links it, and no SDK type reaches a `MakeASoundPlugin` header.
- `MakeASoundAUDescribe` and `MakeASoundAU` (`Plugin/AU/`) are `STATIC` targets, the first built on every Apple platform and the second where `ausdk` exists, which is macOS alone. `MakeASoundAUDescribe` (`ComponentType.cpp`, `HostParameters.cpp`, `Plist.cpp`, `ViewPlacement.cpp`, linking `MakeASoundPlugin`, AudioToolbox and CoreFoundation PUBLIC) is SDK-free and C++20; its property `MAKEASOUND_AU_DESCRIBE_MAIN` is `DescribeMain.cpp`, the `main` of an iOS tree's `<Name>-Describe` (`<bundle name> <bundle id> <executable> <principal class> <0|1> <output>`, `writeAppExtensionPlist` over `describeModule()`). `MakeASoundAUPlistGen`, built beside them, is an executable linking nothing of ours, which loads a module and calls its `MakeASoundAUWritePlist`. `MakeASoundAU` links `MakeASoundPlugin`, `MakeASoundAUDescribe` and `ausdk` PUBLIC and is C++23 through `ausdk`. Its entry, view source, view libraries, export list and `PkgInfo` paths are the target properties `MAKEASOUND_AU_ENTRY`, `MAKEASOUND_AU_VIEW_SOURCE`, `MAKEASOUND_AU_VIEW_LIBRARIES`, `MAKEASOUND_AU_EXPORTS` and `MAKEASOUND_AU_PKGINFO` (always `../VST3/PkgInfo`), which `makeasound_add_plugin` reads. It defines `MAKEASOUND_AU_HAS_VIEW=1` PUBLIC with the view. Only a `<Name>-AU` module compiles the entry and view files, and no SDK type reaches a `MakeASoundPlugin` header.
- `MakeASoundAUv3` (`Plugin/AUv3/`, linking `MakeASoundPlugin`, `MakeASoundAUDescribe`, AudioToolbox, AVFoundation, CoreAudioKit and Foundation PUBLIC) is a `STATIC` Objective-C++ target built on `APPLE`, C++20, `-fobjc-arc -fapplication-extension`. It defines no Objective-C class: the sources on its `MAKEASOUND_AUV3_SOURCES` property are compiled by each module (and the tests) with `MAKEASOUND_AUV3_CLASS_SUFFIX` defined. `MakeASoundAUv3View` (`EmbeddedEditor.mm`, linking `MakeASoundAUv3`, `MakeASoundPluginUI` and `eacp-graphics` PUBLIC) is a second `STATIC` target where the UI tier exists, linked through `MAKEASOUND_AUV3_VIEW_LIBRARIES`.
- `aaxsdk` (`ThirdParty/`) and `MakeASoundAAX` (`Plugin/AAX/`) are `STATIC` targets that exist only with `MAKEASOUND_BUILD_AAX` on macOS, and `aaxsdk` is the only target that compiles Avid's sources. `MakeASoundAAX` links `MakeASoundPlugin` and `aaxsdk` PUBLIC, with the view TUs and `MakeASoundPluginUI`/`eacp-graphics` PRIVATE when those exist and `NoView.cpp` otherwise; it defines `MAKEASOUND_AAX_HAS_VIEW=1` PUBLIC with the view. Its entry, export list, plist template and `PkgInfo` paths are the target properties `MAKEASOUND_AAX_ENTRY`, `MAKEASOUND_AAX_EXPORTS`, `MAKEASOUND_AAX_PLIST` and `MAKEASOUND_AAX_PKGINFO`, and the SDK's `AAX_Exports.cpp` is `aaxsdk`'s `MAKEASOUND_AAX_SDK_EXPORTS`, all read by `makeasound_add_plugin`. Only a `<Name>-AAX` module compiles the entry and the exports, and no SDK type reaches a `MakeASoundPlugin` header.
- always use auto for variables
- platform-specific code goes in per-platform TUs (`Name-macOS.cpp`, `Name-iOS.mm`, `Name-Windows.cpp`, `Name-Linux.cpp`, `Name-Default.cpp`) selected in CMake, the way eacp and `AudioSession-*`/`DeviceQueries*` do, never under `#if` in a shared TU or header
- use modern RAII code whenever possible
- never `git commit` or `git push` without the user's explicit confirmation in that conversation: finish and verify the work, say what is ready to commit, and wait
- branches: `main` takes pull requests from `develop` alone, and `develop` takes pull requests from feature branches; neither is pushed to directly. Cut a feature branch from `develop` and open its pull request against `develop`. GitHub rulesets on both branches enforce it, and `.github/workflows/branch-policy.yml` is the check, required on `main`, that refuses a pull request into `main` from anywhere else.
